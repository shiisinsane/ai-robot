# 附加任务范围与证据原则

> 版本：v1.0  
> 冻结日期：2026-08-19  
> 状态：W0 已确认  
> 适用目录：`portfolio/robot_ops_analytics/`

## 1. 业务场景

本任务将现有 ROS 2 仿真机器人抽象为一台在室内固定区域执行周期性巡检任务的运营对象。
机器人接收巡检目标，执行定位、路径规划、移动和到点感知，并产生任务状态、导航、定位、
传感器和安全数据。

这是求职作品集使用的受控仿真分析案例，不代表已有真实客户、实体设备运营或生产部署。

## 2. 利益相关方与决策问题

假设业务方为机器人运营团队，关注在安全约束下稳定完成更多有效巡检任务。

核心决策问题为：

> 在满足安全护栏的前提下，如何识别容易失败或超时的巡检任务，并通过任务前检查、重定位或
> 模拟人工介入，提高每机器人单位仿真时间内的有效完成任务数？

本案例预期支持以下决策：

- 是否允许任务直接进入导航；
- 是否应在任务前先执行定位检查或重定位；
- 是否应拒绝高风险任务并进入模拟人工检查；
- 哪类路线、障碍场景或参数版本应优先排查；
- 策略提高效率时是否损害安全护栏。

## 3. 分析对象与初步指标范围

主要分析对象为“一次任务执行”。同一业务请求发生重试时，每次执行分别记录，并通过原始请求
标识关联。任务粒度和重试口径已在 W1 指标字典中冻结；有效任务的字段映射将在 W2 数据模型中
落实。

初步北极星指标：

- 每机器人单位仿真时间有效完成任务数。

初步核心指标：

- 任务完成率；
- 准时完成率；
- 任务周期；
- 恢复/介入率；
- 路径效率。

初步护栏指标：

- 最小障碍距离；
- 安全停车率；
- 超速次数；
- 传感器数据过期率。

这些指标在 W0 仅冻结范围。W1 已完成公式、过滤规则和空值处理的冻结；SLA 因尚无基线数据，
按规则保持待冻结。指标用于正式分析或简历陈述前，还需在 W2 后实现并测试可执行 SQL。

## 4. 数据范围

允许复用的已验收仿真数据能力包括：

- M6：任务 ID、任务类型、任务阶段、终态、错误码、取消、超时、并发拒绝和到点快照；
- M5：目标位姿、导航状态、AMCL 位姿、定位误差、恢复、不可达目标和障碍场景；
- M4：TF、里程计、速度、雷达、安全停车、传感器新鲜度和状态估计协方差；
- M1：rosbag 录制、检查、回放、外部证据索引和 SHA-256 规范。

正式分析只使用可追溯到实验 ID、任务 ID、代码提交、配置版本和场景版本的数据。

## 5. 任务范围

本附加任务包括：

- 运营指标树和口径字典；
- 任务、事件、遥测和实验维度数据模型；
- 只读数据采集、实验编排、ETL 和质量检查；
- DuckDB/Parquet 分析层和 SQL 分析；
- 失败风险规则基线、逻辑回归和一种树模型；
- 任务前定位检查、风险任务重定位和模拟人工介入策略；
- 仿真对照实验、业务分析报告、模型卡和简历证据包。

本附加任务不包括：

- M7～M11 实体机器人开发；
- 硬件选型、采购、接线、上电、固件写入或实体运动；
- M12～M17 AI Agent 开发或大模型接入；
- 多机器人调度、真实人力排班和真实维护成本建模；
- 真实客户、收入、成本节省或生产环境效果；
- 对已通过验收的 M4～M6 和 G1 结论进行改写或补充验收。

## 6. 基线保护规则

- 所有新增内容默认保存在 `portfolio/robot_ops_analytics/`。
- 默认只读调用现有 Topic、Service 和 Action，不修改已冻结公共接口。
- 不修改 `docs/planning/`、`docs/backs/milestones/` 或正式阶段状态。
- 不把附加任务结果计入 M4～M6 或 G1 验收。
- 如只读适配确实无法完成任务，必须先记录缺口和替代方案；修改正式项目文件需要用户另行明确
  授权，并进行基线影响评估。
- ROS 2/Gazebo 运行必须使用独立 `ROS_DOMAIN_ID`；并行 Gazebo 必须额外隔离 Transport 分区。

## 7. 可采取动作与安全边界

分析策略只允许在公共任务能力之上选择：

- 正常执行；
- 任务前定位质量检查；
- 通过已验收公共能力请求重定位；
- 拒绝或延后高风险任务；
- 标记为需要模拟人工检查。

分析或模型不得直接发布持续速度命令、绕过安全监督、清除未知故障，或改变正式安全门限。
安全规则始终优先于效率和模型评分。

## 8. 追溯标识规则

### 8.1 实验 ID

格式：

```text
roa-YYYYMMDD-<batch>-<sequence>
```

示例：`roa-20260820-baseline-001`。

实验 ID 标识一次可复现的实验运行。同一实验中可以包含多个任务，但必须共享相同代码、配置、
场景和运行环境基线。

### 8.2 任务 ID

沿用公共任务 Action 的 `task_id`，附加实验建议格式：

```text
<experiment_id>-task-<sequence>
```

重试必须生成新的任务执行 ID，并通过 `request_id` 或 `parent_task_id` 关联原请求。

### 8.3 数据和配置版本

- 数据集版本：`roa-data-v<major>.<minor>`；
- 指标口径版本：`roa-metrics-v<major>.<minor>`；
- 数据模型版本：`roa-schema-v<major>.<minor>`；
- 特征版本：`roa-features-v<major>.<minor>`；
- 模型版本：`roa-model-<family>-v<major>.<minor>`；
- 策略版本：`roa-policy-v<major>.<minor>`。

改变任务粒度、标签、核心口径、数据切分或字段语义时提升主版本；兼容性新增或修正提升次版本。
每份正式证据必须记录 Git 提交和工作区是否干净，不得用版本名替代提交号。

## 9. 数据与 Git 保存策略

| 产物 | 保存策略 |
|---|---|
| DDL、字段字典、指标字典、SQL、ETL、测试 | 提交到附加目录 |
| 小型脱敏确定性样本 | 可提交到 `sample_data/` |
| 业务报告、模型卡、汇总图表 | 提交到 `reports/` |
| 完整 rosbag、原始图像和高频遥测 | 不进入普通 Git，使用受控外部存储 |
| DuckDB、完整 Parquet 和中间加工数据 | 默认不进入普通 Git，保存清单、大小和哈希 |
| 模型二进制和大型解释产物 | 默认不进入普通 Git，保存版本、参数和哈希 |
| 临时日志、缓存和 Notebook 临时输出 | 不作为正式证据，不提交 |

外部产物必须记录相对逻辑位置或受控 URI、大小、SHA-256、生成命令和敏感信息检查结果。不得
提交令牌、私有服务地址、人员隐私或未经审查的室内布局。

## 10. 证据原则

- 正常自然运行样本和故障注入样本必须使用字段明确区分。
- 训练、验证、测试和策略对照数据必须记录不可重叠的切分清单。
- 简历模型数字只来自冻结后的独立测试集。
- 简历策略数字只来自预先定义的受控对照实验。
- 不使用训练集结果、最佳单次结果、计划目标或人工挑选子集作为正式数字。
- 相关性发现必须写作相关性；只有控制变量实验支持时才陈述机制验证，仍不外推真实生产因果。
- 负结果和护栏恶化必须保留，不选择性报告。
- 核心表、指标、图表和模型结果必须能通过固定版本代码和命令复现。
- 文档必须明确“仿真”，不得将结果描述为实体机器人或真实商业运营收益。
