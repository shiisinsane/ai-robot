# M3-W3激光雷达单元验证记录

> 日期：2026年8月4日  
> 结论：通过，允许进入M3-W4相机单元

## 1. 实现范围

- 为机器人描述增加按`enable_lidar`显式启用的`laser_link`、固定关节和GPU Lidar；
- 新增独立场景`m3_lidar.sdf`，前方红色障碍物理论距离1.75 m，左侧绿色障碍物理论距离
  2.25 m；
- 新增`lidar.launch.py`，不启动底盘控制器或运动发布者；
- Gazebo原始数据仅桥接到`/ai_robot_internal/lidar_scan`；
- 薄适配节点`lidar_driver`只保留数据和时间戳、覆盖公共Frame并发布`/robot/scan`；
- 新增`lidar.rviz`和`scripts/check_m3_lidar.py`。

## 2. 首轮问题与修正

| 问题 | 首轮结果 | 修正 |
|---|---|---|
| 原始Frame泄漏实现细节 | `ai_robot/base_link/gpu_lidar` | 薄适配器规范化为`laser_link` |
| 10 Hz配置的墙钟频率不足 | 约7.4 Hz | 仿真更新率调整为15 Hz，公共墙钟频率超过10 Hz |
| 原始桥接方向 | 已使用Gazebo到ROS 2单向桥接 | 保持单向并隔离内部Topic |
| 适配器关闭退出码 | 重复shutdown导致退出码1 | 捕获中断，仅在context有效时shutdown |

以上修正不改变M1公共Topic、消息类型或QoS。

## 3. 最终自动结果

`scripts/check_m3_lidar.py`采集40帧公共扫描并通过全部断言：

| 指标 | 结果 | 要求 |
|---|---:|---:|
| 消息类型 | `sensor_msgs/msg/LaserScan` | 与M1一致 |
| Frame | `laser_link` | 与W2一致 |
| 扫描点数 | 360 | 360 |
| 水平角度 | `-π～π` | 360° |
| 量程 | `0.12～8.0 m` | 与W2一致 |
| 墙钟接收频率 | 11.154 Hz | ≥10 Hz |
| 仿真时间频率 | 15.152 Hz | 约15 Hz |
| 前方障碍距离 | 1.752 m | 1.70～1.80 m |
| 左侧障碍距离 | 2.243 m | 2.20～2.30 m |
| QoS | BEST_EFFORT、VOLATILE | `sensor_stream` |
| 静态TF | `base_link → laser_link`，z=0.10 m | 与W2一致 |

无障碍方向返回非有限量程值，RViz2不绘制这些点；这是标准扫描显示行为，不表示数据缺失。

## 4. 人工图形确认

- Gazebo显示蓝色机器人、顶部黑色雷达、前方红色障碍物和左侧绿色障碍物；
- RViz2显示蓝色机器人以及正前方、左侧两组红色扫描点；
- RViz2扫描点统一使用红色，不继承Gazebo障碍物材质颜色；
- 用户确认上述显示正常，人工图形验收通过。
