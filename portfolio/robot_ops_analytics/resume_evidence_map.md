## 3. 数字来源约束

### R1 指标体系

- 指标名称本身不能证明口径完整；必须提供分子、分母、时间窗口、粒度和过滤规则。
- “人工介入率”只有在采集到明确的人工操作事件后才能使用，否则统一写“恢复/介入率”。
- SLA 由基线实验提出并冻结，不能为获得更好结果在实验结束后调整。

### R2 数据获取与治理

- 数据规模必须同时给出任务数、事件数、遥测聚合行数、时间范围和实验批次数。
- 数据质量成果应报告检测规则、命中数量和处理方式，不能只写“清洗数据”。
- Join 前后任务数必须对账，防止一对多关联虚增业务指标。

### R3 SQL 分析

- “主要异常”至少应报告其样本占比、失败贡献度、效应方向和不确定性。
- SQL 观察得到的是相关性；原因表述必须另有控制变量实验支持。
- SQL、数据版本和输出表必须能一键复现核心结论。

### R4 风险模型

- `N` 指全部符合入组规则的任务数，不只计算训练集或成功读取的样本。
- 模型数字只取冻结后的独立测试集，不能取训练集、交叉验证最佳折或人工筛选子集。
- 数据按批次、路线或场景分组切分，防止近重复任务泄漏。
- 模型特征只使用实际决策时点可获得的数据。

### R5 策略实验

- A、B 和 C 必须来自事先定义的对照实验，而不是模型离线分类指标。
- 对照组和实验组应使用相同或可比的任务矩阵，并记录分配方法。
- 必须同时报告效率指标和安全护栏；护栏恶化时不得只报告效率提升。
- 若策略没有改善，应如实记录，简历不写“提升”。
