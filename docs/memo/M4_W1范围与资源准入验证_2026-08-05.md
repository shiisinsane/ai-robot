# M4-W1范围与资源准入验证记录

> 日期：2026年8月5日
> 结论：通过，允许进入M4-W2集成契约与安全架构

## 1. 范围结论

M4组合M2底盘和M3传感器，交付统一Bringup、局部状态估计、雷达与TF链、RGB基础处理链、
安全监督、故障注入、性能审计和系统回归。M4明确不包含SLAM、`map → odom`、地图、全局
定位、Nav2、目标检测、实体机器人和AI Agent。

## 3. 关键架构风险

1. M2差速控制器当前发布`odom → base_link`，EKF若同时发布将违反唯一权威规则；W2必须先
   冻结切换方案，再接入EKF；
2. M2安全过滤节点当前占用公共`/robot/cmd_vel`，M4安全监督必须重新冻结唯一命令所有权，
   不允许形成并行旁路；
3. M3相机公共图像为Best Effort，而处理节点及可视化工具可能有QoS默认差异；W2必须显式
   冻结订阅与输出QoS；
4. 多传感器和渲染同时运行会降低墙钟频率；W8必须区分仿真时间频率、墙钟频率和实时因子；
5. 诊断只提供可观察性，不能代替停车判定、锁存规则或实体硬件急停。

## 4. 回退边界

- EKF失败时停用融合并恢复M2底盘里程计与TF权威；
- 图像处理失败时保留M3原始图像公共接口，不让处理链阻断原始数据；
- 诊断更新器失败时按关键状态不可用处理，安全规则仍由项目逻辑执行；
- 不修改第三方源码，全部采用配置、Launch和薄封装；
- 未安装依赖前不开展W3～W7运行集成。
