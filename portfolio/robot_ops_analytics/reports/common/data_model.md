# W2 分析数据模型说明

> 版本：roa-schema-v1.0  
> 日期：2026-08-19  
> 状态：W2 已通过，W3 待启动

## 1. 建模目标

数据模型服务三个问题：运营指标如何计算、任务失败如何下钻、风险模型在决策时点能使用哪些
特征。模型不替代 rosbag；rosbag 保存可回放的原始过程，分析仓库保存结构化事实和聚合结果。

## 2. 表关系

```text
dim_experiment ─┬─< fact_robot_operation_window >─ dim_robot
                │
                └─< fact_task_execution >───────── dim_robot
                           │  │  │  │
                           │  │  │  ├────────────── dim_error_code
                           │  │  ├───────────────── dim_parameter_version
                           │  ├──────────────────── dim_route
                           ├─────────────────────── dim_scenario
                           │
                           ├─< fact_task_event
                           └─< fact_task_telemetry_1s
```

中央事实表是 `fact_task_execution`。任务事件和一秒遥测只能通过 `task_id` 与任务事实关联，不能
直接按时间进行无约束 Join。

## 3. 各表解决的问题

| 表 | 一行代表 | 主要用途 |
|---|---|---|
| `dim_robot` | 一个机器人身份有效期 | 机器人小时分母和未来多机器人扩展 |
| `dim_scenario` | 一个版本化实验场景 | 按区域、障碍难度和定位扰动分组 |
| `dim_route` | 一条版本化起终点路线 | 路线复杂度和路径效率分析 |
| `dim_parameter_version` | 一套不可变参数版本 | 区分配置变化，提供速度和新鲜度门限 |
| `dim_error_code` | 一个任务错误码 | 将接口错误码映射为分析终态和失败阶段 |
| `dim_experiment` | 一次可复现实验运行 | 保存代码、配置、环境、分群和有效性 |
| `fact_robot_operation_window` | 一段有效机器人运行区间 | 计算每机器人单位仿真时间完成数 |
| `fact_task_execution` | 一次执行尝试 | KPI、失败标签和任务级特征 |
| `fact_task_event` | 一个有序任务事件 | 漏斗、阶段耗时和异常事件链 |
| `fact_task_telemetry_1s` | 任务内一秒遥测桶 | 安全护栏、定位波动和早期风险特征 |

## 4. 粒度与防重复原则

- `task_id` 唯一标识一次执行尝试；重试生成新 `task_id`，通过 `request_id` 或
  `parent_task_id` 关联。
- 事件使用 `(task_id, event_sequence)` 作为自然唯一键，防止重复消费反馈。
- 遥测使用 `(task_id, bucket_start_sim)` 作为主键，防止同一秒重复聚合。
- 有效运行窗口不得重叠；W5 在计算机器人小时前合并同一实验和机器人的重叠区间。
- 任务指标先在任务粒度计算，再与维度表关联。不能把任务直接 Join 到事件或遥测后执行
  `COUNT(*)`，否则一项任务会被事件数或时间桶数放大。

## 5. 状态规范化

M6 公共契约保留原始错误码，分析层另行规范化：

- 未接受请求：`rejected`；
- 成功：`success`；
- 普通失败：`failed`；
- 取消：`canceled`；
- 错误码 203：`timeout`。

分析规范化不修改 ROS 2 Action 或正式错误码含义。错误码 100～103 的具体请求是否进入运营指标，
仍由 `effective_task` 规则决定；例如非法接口测试通常被排除，并保留在质量或契约测试证据中。

## 6. 时间模型

- 正式任务周期使用 `accepted_at_sim` 到 `terminal_at_sim` 的 ROS 仿真时间差。
- 墙钟时间仅用于证据追溯和环境性能诊断。
- 遥测按一秒 ROS 仿真时间窗口聚合，区间采用左闭右开语义。
- 仿真时钟停止、倒退或跨时钟 Join 会使记录或实验进入质量检查。

## 7. 指标字段覆盖

`data_dictionary.yaml` 已将 W1 的全部指标映射到正式表字段，包括：

- 北极星指标的成功任务分子和机器人小时分母；
- 完成、准时、拒绝、取消和分阶段失败；
- 任务周期、恢复/介入和路径效率；
- 最小障碍距离、安全停车、超速和传感器过期；
- 遥测覆盖率。

可执行指标 SQL 尚未在 W2 实现。W6 将基于实际 ETL 表实现正式分析 SQL；W3/W5 可先实现用于
采集验收和质量对账的最小查询。

## 8. W2 验收结论

- 事实表和维度表的粒度、主键及外键已明确；
- 指标所需字段均有正式落点；
- 任务、事件和遥测的防重复规则已明确；
- 仿真时间和墙钟时间职责已分离；
- M6 错误码已建立分析维度种子；
- DDL 已通过 SQLite 内存库的建表、外键、唯一键和检查约束验证；
- 当前环境没有 DuckDB，DuckDB 引擎执行验证留待 W5 关闭。

W2 验收通过。下一入口为 W3“建立结构化采集和实验编排”，W3 不自动启动。
