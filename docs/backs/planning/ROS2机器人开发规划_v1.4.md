# ROS 2机器人开发规划 v1.4

> 归属：《AI机器人开发项目计划_v1.8》的第一部分详细规划。
> 范围：ROS 2机器人软件层、机器人硬件驱动与本体层。
> 顺序：公共基础 → 模拟机器人 → G1 → 实际机器人 → G2。
> 边界：本规划不开发AI大模型层和AI—ROS 2接口层。

## 1. 开发目标

先形成一套不依赖AI Agent也能独立运行的ROS 2机器人系统，使其具备：

- 底盘运动和安全停车；
- 雷达、相机、IMU和编码器数据接入；
- 里程计、TF和多传感器融合；
- SLAM建图、地图保存和重载；
- 定位、路径规划、运动控制和避障；
- 人员或目标感知；
- 可由CLI、RViz2、测试程序或普通界面调用的机器人能力；
- 完整的诊断、日志、部署、测试和回退能力。

开发原则：

> 成熟资源优先；对象化封装；仿真与实体统一接口；独立节点先测试、子系统再集成、整机最后验收；G1未通过不进入实体，G2未通过不接入AI Agent。

## 2. 范围与边界

### 2.1 ROS 2机器人软件层

负责：

- 机器人模型和TF；
- 底盘控制和里程计；
- 传感器接入及适配；
- 数据融合、SLAM和定位；
- Nav2规划、控制、避障和恢复；
- 非AI机器人任务管理；
- 感知、诊断和安全监督；
- 统一机器人能力接口。

### 2.2 机器人硬件驱动与本体层

负责：

- MCU通信；
- 电机、驱动器和编码器；
- 雷达、相机和IMU实体驱动；
- 电源、电池和设备状态；
- 急停、失联停车及底层保护；
- 实体安装、标定和维护。

### 2.3 不在本规划范围

- 自然语言和多模态任务理解；
- 大模型选择、提示词和工具调用；
- AI任务Schema和语义地点解析；
- AI—ROS 2桥接及AI端到端联调。

这些内容在G2通过后按《AI_Agent开发规划_v1.1》实施。

## 3. 成熟ROS 2资源的获取与使用

### 3.1 引入流程

```text
明确对象和接口
→ 调研成熟资源
→ 核对ROS 2 Humble及Ubuntu 22.04兼容性
→ 建立最小验证样例
→ 完成独立节点和接口契约测试
→ 项目封装与配置
→ 纳入子系统集成
→ 冻结版本并记录来源
```

成熟程序解决通用能力，本项目负责选型、兼容性验证、参数和接口适配、系统集成、硬件协议、标定、安全及测试。

### 3.2 初始候选资源

| 对象能力 | 优先考察资源 | 项目工作 |
|---|---|---|
| 机器人模型 | URDF、Xacro、`robot_state_publisher` | 建立尺寸、关节和传感器安装模型 |
| 差速底盘 | `ros2_control`、`diff_drive_controller` | 配置轮径、轮距和限制；开发实体硬件接口 |
| 仿真平台 | Gazebo及ROS 2桥接/控制插件 | 建立机器人模型、世界、传感器和故障场景 |
| 激光雷达 | 具体品牌的官方或主流ROS 2驱动 | 验证频率、QoS、Frame和`LaserScan` |
| 相机 | USB Camera、RealSense、Orbbec等驱动 | 验证图像、相机参数、帧率和时间戳 |
| 图像处理 | `image_pipeline`、`image_transport` | 校正、压缩、格式和传输配置 |
| IMU/里程计融合 | `robot_localization` | 建立EKF配置、协方差和坐标约定 |
| 坐标变换 | `tf2`、`robot_state_publisher` | 设计并持续验证TF树 |
| SLAM | `slam_toolbox` | 配置建图、地图保存和定位模式 |
| 定位和导航 | Nav2、AMCL | 配置规划器、控制器、代价地图和行为树 |
| 视觉识别 | OpenCV、YOLO及ROS 2封装 | 选择模型并统一检测结果接口 |
| 数据记录 | `rosbag2` | 建立测试数据集、问题复现和回放测试 |
| 可视化诊断 | RViz2、`rqt`、ROS 2 CLI、diagnostics | 建立调试与验收视图 |

候选资源必须经过准入，不因“成熟”而免除项目测试。

### 3.3 资源卡和准入标准

每个第三方资源至少记录：

- 项目名称、来源和许可证；
- 维护状态、发行版及锁定版本；
- ROS 2 Humble和Ubuntu 22.04兼容性；
- 安装方式、依赖和可重复构建方法；
- Topic、Service、Action、QoS、TF、时间戳和参数要求；
- CPU、GPU、内存、网络和设备需求；
- 仿真实现、实体实现及替代方案；
- 最小验证结果、已知问题和回退方式。

准入要求：

1. 来源和许可证满足项目要求；
2. 能在基线环境构建或安装；
3. 最小样例可稳定启动、停止和重启；
4. 接口可适配项目约定；
5. 关键输出可自动检查；
6. 异常不会绕过安全控制；
7. 版本、配置和安装过程可复现。

原则上不直接修改第三方源码。优先使用参数、适配节点或薄封装；确需修改时，记录补丁原因、测试和上游版本。

## 4. 面向对象与模块化设计

| 对象 | 典型实现 | 主要职责 |
|---|---|---|
| 底盘对象 | `BaseDriverNode` | 接收速度命令，发布里程计和设备状态 |
| 雷达对象 | 雷达驱动/适配节点 | 发布标准激光扫描数据 |
| 相机对象 | 相机驱动/适配节点 | 发布图像与相机参数 |
| IMU对象 | IMU驱动/适配节点 | 发布惯性数据及状态 |
| 定位对象 | 融合与定位节点 | 发布稳定的位姿和坐标变换 |
| 导航对象 | Nav2能力封装 | 接收目标、反馈进度并支持取消 |
| 感知对象 | `PerceptionNode` | 输出标准化目标检测结果 |
| 安全对象 | `SafetySupervisorNode` | 限速、超时、急停和命令仲裁 |
| 任务对象 | `TaskManagerNode` | 执行非AI机器人能力状态机和异常处理 |

节点内部采用类封装状态和行为；算法、协议和任务规则尽量放入不依赖ROS 2的普通类，以便单元测试。

每个对象应满足：

1. 职责和边界明确；
2. 成熟资源或自研方案确定；
3. 接口、参数、QoS和TF有文档；
4. 仿真与实体替换关系明确；
5. 自研代码单元测试通过；
6. 独立节点或接口契约测试通过；
7. 至少一个相关子系统集成测试通过；
8. 日志、诊断和异常行为可观察；
9. 版本、配置和测试证据归档。

## 5. 仿真与实体统一接口

| 能力 | 仿真实现 | 实体实现 | 上层接口 |
|---|---|---|---|
| 底盘 | Gazebo/控制插件 | MCU和实体底盘驱动 | `/cmd_vel`、`/odom`、TF |
| 激光雷达 | 仿真雷达 | 实体雷达驱动 | `/scan` |
| 相机 | 仿真相机 | 实体相机驱动 | `/camera/*` |
| IMU | 仿真IMU | 实体IMU驱动 | `/imu/data` |
| 安全状态 | 故障注入节点 | 急停、电池和设备状态 | 统一安全/诊断接口 |

```text
mode:=sim   → 加载仿真驱动、仿真传感器和仿真参数
mode:=real  → 加载实体驱动、实体传感器和实机参数
```

任务管理和机器人能力接口不感知底层是仿真还是真机。若实体迁移迫使修改公共接口，应暂停并检查是否发生架构泄漏。

## 6. 测试体系

### 6.1 测试层级

| 级别 | 测试对象 | 主要方法 | 示例 |
|---|---|---|---|
| T1 代码单元测试 | 自研普通类和算法 | 白盒、无ROS或最小ROS依赖 | 协议编解码、坐标转换、状态机 |
| T2 独立节点测试 | 单个自研或第三方节点 | 黑盒、接口契约、参数和生命周期测试 | 相机、雷达、底盘和IMU |
| T3 子系统集成测试 | 多个相关节点 | Launch测试、录包回放和故障注入 | 底盘闭环、雷达+TF+SLAM、地图+定位+Nav2 |
| T4 ROS 2系统测试 | 完整机器人软件 | 仿真场景、重复运行和性能检查 | 建图、定位、导航、避障和安全停车 |
| T5 实体安全与机器人验收 | 真实机器人 | 架空、低速、限定区域和长稳测试 | 急停、失联停车、导航和任务执行 |

第三方成熟包通常不重复其内部源码白盒测试，重点验证：

- 启动、停止、重启和生命周期；
- Topic、Service、Action和参数；
- 消息类型、频率、时间戳、QoS和Frame；
- 输入异常、设备断开或数据超时；
- 与上下游组合后的系统指标。

### 6.2 自底向上

```text
雷达/相机/IMU/底盘等独立节点
→ 运动、感知、定位、导航和安全子系统
→ ROS 2整机系统
```

典型子系统：

- 底盘控制＋编码器＋里程计＋TF；
- 雷达＋TF＋SLAM；
- IMU＋编码器＋`robot_localization`；
- 地图＋定位＋Nav2；
- 相机＋图像处理＋目标检测；
- 安全节点＋速度命令＋底盘控制。

### 6.3 自顶向下

从“建图、导航、感知、安全停车”等目标能力反推节点接口和验收场景，但不在本阶段引入大模型。测试程序可直接调用结构化机器人能力，以尽早发现接口和状态反馈问题。

## 8. 公共基础

### 8.1 M0：环境与工程基线

主要工作：

- 核实Ubuntu 22.04、ROS 2 Humble、内核、显卡、磁盘和网络；
- 验证`colcon`、示例节点、RViz2和Gazebo；
- 建立工作空间、Git仓库、依赖清单和统一构建入口；
- 配置VS Code、C++、Python、CMake及调试环境；
- 建立环境自检、日志、版本、提交和文档规则；
- 建立`AGENTS.md`，明确Codex的改动和测试边界。

交付环境自检报告、工程目录、依赖安装说明、统一构建与测试命令及首个Git基线。

### 8.2 M1：资源、接口与测试基线

- 建立“对象—候选资源—仿真实现—实体实现—测试方法”矩阵；
- 建立第三方资源卡和准入流程；
- 确定Topic、Service、Action、消息、QoS和命名规范；
- 建立`map → odom → base_link → sensor_link`坐标系规范；
- 建立最小C++节点、Python节点和测试样例；
- 建立单元、Launch、契约和场景测试目录；
- 建立rosbag记录、回放和测试证据模板。

M1不要求一次确定全部硬件品牌，但必须明确每类硬件的接口和选择条件。

## 9. 第一阶段：模拟机器人开发

### 9.1 M2：仿真本体与底盘单元

1. 建立URDF/Xacro模型和TF；
2. 接入成熟差速控制资源；
3. 独立验证速度命令、轮速、里程计、转向和停车；
4. 验证命令超时停车、速度限制和生命周期；
5. 固化底盘接口契约测试。

验收要求：前进、后退、原地转向和停车正确；`/cmd_vel`、`/odom`和TF方向一致；模型无明显异常；自动测试可重复。

### 9.2 M3：仿真传感器单元

每类传感器必须单独启动、观察和测试：

| 对象 | 独立测试重点 |
|---|---|
| 激光雷达 | 扫描角度、距离、频率、噪声、时间戳、QoS和Frame |
| 相机 | 分辨率、帧率、编码、相机参数、时间戳和Frame |
| IMU | 角速度、加速度、方向、协方差、频率和Frame |
| 仿真编码器 | 左右轮方向、累计量、分辨率和里程计关系 |

每个对象形成独立启动文件、默认参数、诊断配置、自动接口检查、rosbag样本和测试记录。

### 9.3 M4：运动、感知与安全集成

组合测试：

- 底盘＋编码器＋里程计＋TF；
- 编码器＋IMU＋`robot_localization`；
- 雷达＋TF＋障碍物数据链；
- 相机＋图像处理；
- 安全节点＋速度命令＋底盘。

重点验证启动顺序、时间同步、QoS、TF完整性、资源占用、异常传播和安全停车。

### 9.4 M5：SLAM、定位与Nav2

```text
雷达和里程计契约通过
→ SLAM建图
→ 地图保存和重载
→ AMCL或定位模式
→ Nav2全局规划
→ 局部控制和避障
→ 恢复行为和任务取消
```

测试固定路线多次到点、静态和临时障碍、定位初始偏差、导航取消、传感器超时和不可达目标。

### 9.5 M6：仿真机器人综合验收

```text
测试程序下达机器人能力任务
→ ROS 2任务管理器校验
→ Nav2仿真导航
→ 到点执行感知
→ 返回任务状态和结果
```

不接入大模型。覆盖越界、不可达、失败、超时、取消、数据中断、安全触发、重复执行和资源占用。

## 10. G1：仿真到实体准入

全部满足后才能进入实体开发：

- 关键对象具有明确接口、配置和责任边界；
- 仿真底盘、雷达、相机和IMU独立测试通过；
- 运动、感知、定位、导航和安全集成测试通过；
- 仿真整机可稳定建图、定位、导航和避障；
- 正常、异常、取消、超时和故障注入通过；
- 自动回归和日志可定位到节点或子系统；
- 仿真与实体统一接口冻结；
- 硬件和ROS 2驱动兼容性完成审查；
- MCU、急停、通信失联和速度限制方案确定。

输出：

- 《仿真阶段测试报告》；
- 《实体接口冻结清单》；
- 《实体硬件与成熟资源选型表》；
- 《实体调试安全方案》；
- 是否准入实体阶段的明确结论。

## 11. 第二阶段：实际机器人开发

### 11.1 M7：实体资源定型与安全准备

- 底盘、MCU、电机驱动、编码器、雷达、相机和IMU选型；
- 驱动的ROS 2 Humble兼容性PoC；
- USB、Ethernet、串口和CAN拓扑设计；
- 电源、算力、带宽和安装空间核算；
- 急停、安全回路、保险和调试支撑方案；
- 实体参数、驱动版本及替代方案冻结。

### 11.2 M8：实体设备单元测试

```text
MCU协议离线测试
→ 电机架空测试
→ 编码器方向与计数测试
→ 底盘低速直线/旋转测试
→ 雷达独立测试
→ 相机独立测试
→ IMU独立测试
→ 急停和通信失联测试
```

复用模拟阶段接口契约，只新增实体特有的时延、丢包、温度、供电、标定和断连测试。

### 11.3 M9：实体运动、感知与安全集成

- 建立底盘、编码器、里程计和TF闭环；
- 标定轮径、轮距、速度和转向；
- 融合编码器和IMU；
- 标定雷达和相机外参；
- 联调安全节点、急停和MCU保护；
- 验证手动/自动控制切换；
- 联合记录rosbag和设备日志。

调试从架空、低速和限定区域逐步扩大，始终保留人工急停。

### 11.4 M10：实体SLAM、定位与Nav2

复用模拟软件包和接口，仅调整实体TF、标定、噪声、协方差、里程计、定位、代价地图、机器人轮廓、规划器、控制器及速度限制。

除复用仿真场景外，增加网络中断、MCU异常、传感器断连、电量不足、定位漂移、动态障碍和人工急停恢复。

### 11.5 M11：ROS 2机器人稳定化

交付：

- 安装和部署脚本；
- 实体参数、地图和模型版本；
- 操作、调试和维护手册；
- 节点、子系统和整机测试报告；
- 故障诊断和日志采集说明；
- 成熟资源、版本和许可证清单；

## 12. G2：ROS 2机器人能力验收

全部满足后才能启动AI Agent开发：

- 实体机器人独立完成建图、定位、导航、避障、感知和安全停车；
- 仿真与实体的公共能力接口一致；
- 能力可通过Action、Service或受控Topic调用；
- 每项能力有成功、失败、取消、超时和状态反馈；
- 关键对象均有独立测试；
- 子系统、整机、实体安全和长稳测试通过；
- 接口、消息Schema、QoS、TF和错误码冻结；
- 仿真和实体测试环境可重复部署；
- 不存在阻止AI接入的严重缺陷。

输出：

- 《ROS 2机器人能力清单》；
- 《ROS 2机器人综合验收报告》；
- 《AI调用接口冻结说明》；
- 《仿真与实体回归测试集》；
- 是否准入AI Agent开发的明确结论。
