## 2. 状态估计与TF权威

- 整机模式下将差速控制器原始里程计隔离为`/robot/internal/base_odom`；
- `robot_localization/ekf_node`输入原始里程计和`/robot/imu/data`；
- EKF输出继续使用M1公共`/robot/odom`；
- `world_frame=odom`、`base_link_frame=base_link`、`two_d_mode=true`；
- 整机模式关闭差速控制器TF，由状态估计器唯一发布`odom → base_link`；
- M2独立Launch继续保留原控制器里程计与TF，作为融合失败时的已验收回退路径。

## 3. 安全命令链

冻结唯一命令链：

```text
/robot/cmd_vel
→ safety_supervisor
→ /robot/safety_cmd_vel
→ cmd_vel_safety_filter
→ /robot/controller_cmd_vel
→ diff_drive_base_controller
```

安全监督独占公共入口，禁止控制器或过滤器直接订阅公共命令。M2过滤器继续负责非有限值、
限速和加速度限制，M4监督器负责输入新鲜度、故障锁存、诊断和清除条件。

停车级监控包括命令、原始里程计、IMU、雷达和非有限命令；相机超时为WARN，不阻止手动
安全停车。故障清除必须同时满足零命令、全部停车级输入恢复以及显式Service调用。

## 4. 图像、诊断和性能

- `image_proc/rectify_node`订阅M3原始RGB图像与`CameraInfo`；
- 输出`/robot/camera/color/image_rect`，保持Best Effort、时间戳和光学Frame；
- 处理延迟仿真时间门限为`0.1 s`；
- 标准诊断使用`diagnostic_msgs/msg/DiagnosticArray`，目标10 Hz；
- 初始系统门限：实时因子不低于0.5、总CPU不高于400%、RSS不高于2048 MiB；
- 性能门限将在W8以30秒窗口实测，若环境差异显著必须记录而非静默放宽。
