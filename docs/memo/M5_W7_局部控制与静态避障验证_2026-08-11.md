# M5-W7 局部控制与静态避障验证记录

> 日期：2026年8月11日
> 结论：通过，允许进入M5-W8临时障碍、恢复与取消。

## 1. 完成内容

- 接入Nav2 Controller Server、BT Navigator和生命周期管理器；
- 采用`RegulatedPurePursuitController`沿全局路径闭环控制；
- 建立带雷达障碍层和膨胀层的滚动局部代价地图；
- 通过薄适配器将内部Nav2 Action接到M1冻结的
  `/robot/navigation/navigate_to_pose`公共接口；
- 控制器输出只进入`/robot/cmd_vel`，继续由M4安全监督器仲裁后驱动底盘；
- 使用一次规划、一次跟踪且不含恢复节点的静态行为树，避免提前实现W8能力；
- 新增公共Action、实际到点、运动命令、局部代价地图和障碍间距检查器。

## 2. 参数与边界

全局规划膨胀半径由W6的`0.35 m`调整为`0.55 m`，局部代价地图膨胀半径为
`0.45 m`，为矩形车体留下可执行的转弯余量。目标检查器位置/角度容差分别为
`0.10 m / 0.15 rad`。RPP启用碰撞预测、代价调速和原地朝向调整。

W7只验证地图中已有的静态障碍。行为树不包含周期重规划、后退、旋转、等待或清图恢复；
临时障碍、恢复、取消和失败反馈留给W8。

`landmark_a`，因此直行不可到达。运行结果：

## 4. 确定性静态避障GUI复验步骤

本节用于复验已经通过的W7静态避障场景，不扩展W7范围。推荐采用“Gazebo/Nav2服务端先行、
位姿单独核对、检查脚本最后执行”的三个终端流程。所有终端必须使用相同且独立的
`ROS_DOMAIN_ID`，避免本机其他ROS 2节点污染Topic、TF和生命周期状态。

### 4.1 前置条件

- 已完成工作区构建，`install/setup.bash`存在；
- W4保存的地图YAML及对应PGM存在；以下命令使用本轮W9临时地图
  `/tmp/ai_robot_m5_w9_maps/m5_w9_runtime.yaml`，若文件已被系统清理，应先按W3/W4流程重新
  建图和保存，不得用不存在或来源不明的地图继续测试；
- 没有遗留的Gazebo、Nav2或同一ROS域进程；
- 全程只操作仿真机器人，不连接实体设备。

### 4.2 终端一：启动Gazebo和导航栈

```bash
cd /home/yangyiyao/ai_robot
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=59
export ROS_LOG_DIR=/tmp/ai_robot_ros_logs

ros2 launch ai_robot_sim m5_recovery_navigation.launch.py \
  gui:=true \
  map:=/tmp/ai_robot_m5_w9_maps/m5_w9_runtime.yaml
```

虽然该入口包含W8的周期重规划和受限恢复，但复验目标仍是地图内固有静态障碍
`landmark_a`，不移动`temporary_obstacle`，也不把恢复行为当作W7通过依据。等待Gazebo中
机器人生成，并确认Map Server、AMCL、Planner Server、Controller Server和BT Navigator均
完成激活后再继续。

### 4.3 终端二：核对机器人实时位姿

```bash
cd /home/yangyiyao/ai_robot
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=59
export ROS_LOG_DIR=/tmp/ai_robot_ros_logs

ros2 run tf2_ros tf2_echo map base_link
```

必须先确认机器人实际位于原点附近且朝向与冻结场景一致，不能只按世界坐标假设起点。冻结
场景的目标为`(2.2, 1.8)`，静态障碍`landmark_a`中心为`(1.7, 1.4)`；从原点到目标的直线
穿过障碍，因此几何关系保证机器人必须绕行。如果机器人已被此前任务移动，应重启仿真恢复
起点，或重新设计并记录能确保障碍位于起终点之间的场景，不直接套用原参数。

### 4.4 终端三：执行静态避障检查

```bash
cd /home/yangyiyao/ai_robot
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=59
export ROS_LOG_DIR=/tmp/ai_robot_ros_logs

python3 scripts/check_m5_local_control.py \
  --goal-x 2.2 \
  --goal-y 1.8 \
  --goal-yaw 0.0 \
  --timeout 90 \
  --obstacle-x 1.7 \
  --obstacle-y 1.4 \
  --minimum-center-clearance 0.4
```

### 4.5 GUI观察与通过标准

复验只有在人工观察和机器证据同时成立时才判定通过：

- Gazebo中小车明显从`landmark_a`侧面绕过，没有直穿或碰撞；
- 障碍在整个导航过程中保持静止，并始终符合起点、障碍、目标的冻结几何关系；
- 小车最终到达障碍另一侧的目标附近并停车，没有持续振荡；
- 公共Action返回`SUCCEEDED`，脚本输出“M5-W7局部控制检查通过”；
- 位置误差和角度误差分别不超过`0.15 m`和`0.15 rad`；
- 障碍中心最小距离不低于`0.4 m`，局部代价地图存在致命障碍格；
- 速度命令继续通过M4公共安全监督链，不出现控制器直达底盘的旁路。

Action成功不能单独证明绕障。如果脚本成功但GUI没有看到侧向绕行，或者起点已变化导致障碍
位于车后，应撤回本次人工结论，重新核对`map → base_link`和场景几何关系后复测。

### 4.6 常见异常与处理

- 启动期可能出现传感器尚未稳定导致的安全锁存；先等待雷达、IMU和里程计稳定，检查脚本会
  持续发送零速度并尝试清除故障，不得放宽M4的`0.2 s`安全门限；
- 若Planner Server没有进入`active`，应先通过`ros2 lifecycle get
  /robot/planner_server`确认状态；未激活时不继续发目标，应关闭整套Launch并从干净状态重启，
  不把手工激活作为正式复验的默认流程；
- 若地图、雷达点和机器人模型不对齐，或TF缺少`map → odom → base_link`主链，应终止测试并
  排查地图、AMCL和TF权威，不能依据Action结果继续判定；
- 验证结束后先确认小车停车，再在终端一按`Ctrl+C`统一关闭仿真和导航节点。
