# M6-W4 导航任务编排验证记录

> 日期：2026年8月12日
> 结论：通过，允许进入M6-W5到点感知与结果。

## 1. 完成内容

- 任务管理器新增M5公共`NavigateToPose` Action客户端，不调用Nav2内部Action；
- 结构化任务通过校验后进入`NAVIGATING`，发送相同`map`目标位姿；
- Nav2剩余距离以不高于5 Hz映射为任务反馈，进度保持单调且限制在导航阶段范围；
- 导航成功后进入`SENSING`；W5尚未接入时明确以`ERROR_SENSOR_UNAVAILABLE`结束；
- 导航拒绝、失败、取消分别映射为稳定任务错误码；
- 用户取消、任务/导航超时和安全停车都会取消下游导航目标；
- 安全停车优先于用户取消和普通失败，任务管理器仍不发布速度命令；
- 地图订阅改用Reliable、Transient Local QoS，确保后启动的任务管理器可校验地图边界。

## 2. 端到端结果

在隔离ROS Domain 217启动Gazebo、M5完整导航栈和M6任务管理器，通过
`/robot/task/execute`下发`(0.4, 0.0, 0.0)`目标：

```text
任务反馈阶段：ACCEPTED → VALIDATING → NAVIGATING → SENSING
下游Nav2 Action：SUCCEEDED
最终位置误差：0.096 m
任务Action：ABORTED
任务错误码：ERROR_SENSOR_UNAVAILABLE
```

任务Action本轮返回`ABORTED`是预期阶段边界：导航已经成功，但完整任务还要求W5的到点感知
快照；在快照尚未实现时不得返回任务成功。

## 3. 启动与安全经验

首次两轮测试在启动期以`ERROR_SAFETY_STOP`失败。原因不是导航编排错误，而是任务Action早于
Nav2生命周期完整就绪，测试过早清除启动期传感器锁存，随后EKF输入短暂不稳定再次触发安全
停车。最终入口先等待公共导航Action和短暂稳态窗口，再持续发布零速度到任务目标被接受，由
Nav2立即接管命令源。运行中没有测试程序速度与Nav2速度并行发布。

一次0.8 m运行的Nav2日志已记录`Goal succeeded`，但工具会话编号超出轮询范围，未作为正式
汇总证据；随后0.4 m场景在新隔离域取得完整客户端结果并通过。

## 5. GUI人工复验步骤

2026年8月12日，用户按下列流程完成GUI现场复验，确认任务下发后小车在Gazebo中正常导航到
目标，结论为“GUI验证通过”。以下步骤作为M6-W4可复用的人工验证入口。

### 5.1 前置条件

- 已完成工作区构建，`install/setup.bash`存在；
- M5-W10归档地图YAML及其引用的PGM存在；
- 没有遗留的Gazebo、Nav2、任务管理器或同一ROS Domain进程；
- 三个终端必须使用相同且独立的`ROS_DOMAIN_ID`，全程只连接仿真机器人。

### 5.2 终端一：启动Gazebo和M5导航栈

```bash
cd /home/yangyiyao/ai_robot
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=218
export ROS_LOG_DIR=/tmp/ai_robot_ros_logs

ros2 launch ai_robot_sim m5_recovery_navigation.launch.py \
  gui:=true \
  map:=/home/yangyiyao/ai_robot/artifacts/m5_w10/20260812_112602/config_snapshot/m5_w10_map.yaml
```

等待Gazebo中机器人和环境完整生成，并等待Map Server、AMCL、Planner Server、Controller
Server和BT Navigator全部激活后再继续。地图归档路径若因证据迁移而变更，必须改用同一
M5-W10快照内的YAML，不使用临时或来源不明的地图。

### 5.3 终端二：启动M6任务管理器

```bash
cd /home/yangyiyao/ai_robot
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=218
export ROS_LOG_DIR=/tmp/ai_robot_ros_logs

ros2 launch ai_robot_task_manager task_manager.launch.py
```

确认日志中任务管理器已启动，且`/robot/task/execute`可被发现。任务管理器不直接发布速度，
实际运动仍经M5公共导航Action和安全链执行。

### 5.4 终端三：下发结构化任务并自动核对

```bash
cd /home/yangyiyao/ai_robot
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=218
export ROS_LOG_DIR=/tmp/ai_robot_ros_logs

python3 scripts/check_m6_navigation_task.py \
  --goal-x 0.4 \
  --goal-y 0.0 \
  --goal-yaw 0.0 \
  --timeout 180 \
  --position-tolerance 0.15
```

该脚本会等待任务和导航Action就绪，在任务被接受前持续发布零速并清除可恢复的启动期安全
锁存；任务接受后立即停止测试零速发布，由Nav2接管速度源，避免与导航命令并行。

### 5.5 人工观察点与通过标准

- Gazebo中小车从原点附近开始运动，无瞬移、异常冲出或持续非零速度遗留；
- 小车实际到达`(0.4, 0.0)`附近，脚本计算的`map → base_link`位置误差不超过`0.15 m`；
- 脚本输出“M6-W4导航任务编排检查通过”，反馈阶段包含`ACCEPTED`、`VALIDATING`、
  `NAVIGATING`和`SENSING`；
- W5尚未实现时，最终`ABORTED + ERROR_SENSOR_UNAVAILABLE`是预期的阶段边界，不代表导航失败；
- 停止复验时用`Ctrl+C`依次结束终端三、终端二和终端一，确认仿真进程正常退出。
