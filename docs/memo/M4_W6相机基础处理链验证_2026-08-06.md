# M4-W6相机基础处理链验证记录

> 日期：2026年8月6日
> 结论：通过，允许进入M4-W7安全监督与故障注入

## 1. 实现范围

- 在统一Bringup中接入`image_proc/rectify_node`，输出基础校正图像；
- 将`image_proc`输出隔离为内部Reliable Topic，再由薄适配器发布公共Best Effort
  `/robot/camera/color/image_rect`，保持M4-W2冻结的公共QoS契约；
- 新增`enable_image_processing`启动参数，可单独关闭图像处理链实施故障注入；
- 新增`check_m4_image_processing.py`，检查原始/处理图像对应关系、格式、时间戳、Frame、
  延迟、频率、CameraInfo及故障隔离；
- 本阶段只完成基础图像校正，不实现目标检测、视觉定位、SLAM或AI Agent。

## 2. 正常运行验证

在隔离的ROS 2 Domain和独立Gazebo分区中运行整机，取得20组原始图像与处理图像：

- 每组原始/处理图像时间戳完全一致且严格递增；
- 图像均为640×480、`rgb8`，Frame为`camera_color_optical_frame`；
- 行步长和数据长度与编码、分辨率一致；
- CameraInfo分辨率和Frame与图像匹配；
- 最大仿真时间处理延迟为`0.020 s`；
- 公共处理图像只有一个发布者，为QoS适配器，可靠性为Best Effort；
- 本次整机环境实测处理图像频率为`4.429 Hz`。

## 3. 故障隔离验证

使用`enable_image_processing:=false`启动隔离场景，并运行
`check_m4_image_processing.py --expect-timeout`：

- 5秒窗口内原始图像收到21帧；
- 同一窗口内处理图像收到0帧，确认处理链确实关闭；
- 同一窗口内融合里程计收到128条；
- 结论是图像处理节点失效不会阻断原始相机源，也不会拖垮状态估计链；
- 故障诊断、锁存和安全停车属于W7，本阶段不提前宣称其通过。

## 4. 回归验证

- 4个ROS 2软件包构建通过；
- 包内33项测试通过；
- 仓库级39项测试通过；
- 接口契约、机器人模型、传感器模型、M4集成配置和仿真资源检查通过；
- `git diff --check`通过；
- 未连接实体设备或AI Agent。

## 5. 已知边界

- 当前图像校正输入使用仿真相机标定数据，不代表实体相机标定已完成；
- 整机无界面渲染环境中图像频率仅为`4.429 Hz`，低于相机配置目标频率；W6只验证处理链
  的数据契约和故障隔离，频率、实时因子、CPU及内存是否达到冻结指标必须由W8统一判断；
- 运行日志出现图像与CameraInfo未同步警告，原因是资源受限时图像产出慢于CameraInfo；已接收
  的20帧图像均找到时间戳完全一致的CameraInfo和处理输出，但该现象仍作为W8性能观察项；
- 本阶段未进行用户GUI人工验证，运行时自动检查不能替代后续需要的视觉效果确认。
