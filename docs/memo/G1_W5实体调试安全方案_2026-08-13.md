# G1-W5实体调试安全方案

> 日期：2026年8月13日
> 结论：设计审查通过
> 机器可读方案：`../../config/common/g1_entity_safety_plan.yaml`

## 1. 适用范围与边界

本方案规定M7～M10实体调试的最低项目流程，用于降低首次上电、首次转轮和首次落地运动风险。
它不构成功能安全认证，不替代机械、电气、消防、电池、激光、工作场所法规或专业风险评估。

ISO 13850:2015给出机械急停功能的设计原则；ISO 3691-4:2023覆盖无人驾驶工业车辆及其系统，
并强调运行区域条件会显著影响安全。项目在具体用途、地区和硬件确定后必须由具备资质的人员
确认适用标准与法规：[ISO 13850](https://www.iso.org/standard/59970.html)、
[ISO 3691-4](https://www.iso.org/standard/83545.html)。

G1只冻结方案，不连接硬件、不上电、不运动、不写设备，也不修改安全回路。

## 2. 核心原则

- 先完成书面风险评估和停止条件，再允许任何有动力测试；
- 急停是补充保护，不是正常停车方式，也不能替代防护、限速和安全距离；
- 急停独立于ROS、上位机、DDS和普通通信总线，动作后移除电机扭矩；
- 急停或故障复位只解除锁存，绝不自动重新使能或恢复运动；
- 断电、欠压、通信失联、进程退出和协议错误都必须进入安全方向；
- 首次转轮及以后所有落地运动至少两人在场，一人专职掌握急停；
- 任何人都可以喊停，停止决定不需要技术负责人批准；
- 不靠关闭看门狗、安全监督或诊断来让测试“通过”。

## 3. 角色与现场责任

| 角色 | 责任 |
|---|---|
| 测试负责人 | 定义范围、命令源、参数、通过/中止条件，作出Go/No-Go决定 |
| 安全操作员 | 专职掌握硬件急停，监控排除区，不同时操作终端 |
| 观察记录员 | 记录证据、异常和时间线；可与测试负责人兼任，但不可替代安全操作员 |

有动力测试最少两人。人员必须在测试前明确口令：“准备”“使能”“停止”“急停”“断电”。
禁止佩戴影响听觉/视野的设备，禁止无关人员、儿童或宠物进入排除区。

## 4. 六级调试门禁

| 门禁 | 范围 | 运动限制 | 放行条件摘要 |
|---|---|---|---|
| G0 | 文档与无动力检查 | 禁止运动 | 原理图、保险、极性、接地、机械紧固、风险表完成 |
| G1 | 仅逻辑电源 | 禁止电机使能 | 上位机、MCU、传感器、诊断和身份正常，动力支路断开 |
| G2 | 电机架空 | `0.05 m/s`、`0.20 rad/s` | 机器人可靠支撑，轮周无物，急停和失联先实测 |
| G3 | 约束/阻挡低速 | `0.05 m/s`、`0.20 rad/s` | 牵引约束或物理挡块不引入倾覆/缠绕风险 |
| G4 | 封闭区域手动低速 | `0.10 m/s`、`0.30 rad/s` | 停止距离实测，排除区清空，安全操作员就位 |
| G5 | 封闭区域自动运动 | `0.20 m/s`、`0.60 rad/s` | G4通过，定位/雷达/安全链健康，任务范围与路线固定 |

这些是调试上限，不是最终产品速度。若风险评估、场地或停止距离要求更低，以更低值为准。
任何门禁失败必须退回前一级；更换电机、驱动、轮径、MCU固件、安全回路或核心控制参数后，
至少退回G1，涉及运动方向或制动时退回G2。

## 5. 上电与下电顺序

### 上电前

1. 记录硬件料号、接线版本、固件、软件提交和参数；
2. 机械支撑、轮区、保险、极性、线束、散热和电池状态检查通过；
3. 急停按下，电机动力禁止，上位机命令为零；
4. 明确唯一命令源，关闭自动任务和未授权遥控节点；
5. 安全操作员确认急停可达，排除区建立。

### 上电

1. 接通逻辑/诊断电源，保持电机动力禁止；
2. 启动MCU和实体驱动，确认协议版本、设备身份、心跳和故障状态；
3. 启动适配器、状态估计和安全监督，确认必需Topic新鲜、TF唯一；
4. 实测硬件急停、命令超时和通信断开均能阻止电机扭矩；
5. 零命令、故障复核和人工确认后，才允许进入当前门禁的电机使能步骤。

### 下电

先发零命令并确认停止，取消任务，禁用电机驱动，断动力支路，再停止ROS/MCU和逻辑电源。
遇烟、异味、过热、失控或电气异常时直接急停并按风险评估断电，不为保存日志延迟人员保护。

## 6. 急停、使能与复位

- 急停采用常闭或等效失效安全结构，断线、断电应进入禁止扭矩状态；
- 急停直接作用于驱动使能/动力安全路径，并把状态反馈给MCU和ROS诊断；
- 急停按钮在测试人员无需跨越机器人路径的位置，架空和落地测试都可立即触达；
- 急停必须锁存，机械释放后仍保持运动禁止；
- 复位至少需要人工动作、零命令、故障原因复核、关键输入新鲜和明确重新使能；
- 上位机重启、MCU重启、网络恢复或急停释放都不得自动产生运动；
- 每次新门禁首次测试、接线变化和每日开始前均实测急停。

## 7. 软件安全、失联与异常处理

冻结门限保持不变：命令、里程计和IMU超时`0.2 s`，雷达超时`0.5 s`。MCU还必须有独立主机
心跳超时，具体值在M7按控制周期冻结，但不得慢于会造成不可接受停止距离的水平。

| 故障 | 必须动作 |
|---|---|
| 非有限或越界速度 | 拒绝命令、锁存停车、记录错误 |
| 主机/MCU/CAN/UART失联 | MCU目标归零、禁止或受控撤销扭矩、ROS锁存停车、任务失败 |
| 编码器/里程计/IMU/雷达断流 | 锁存停车，禁止自动恢复任务 |
| 相机断流 | 停止依赖相机的任务；是否停车按当前安全功能评估，不静默使用旧图像 |
| 欠压、过流、过温、驱动故障 | 禁止扭矩并保持故障，人工检查后复位 |
| 定位丢失、TF冲突或方向错误 | 取消导航并停车，不以里程计猜测继续自动行驶 |
| 上位机或节点重启 | 默认零命令、禁止自动恢复先前任务 |

## 8. 强制停止条件

出现以下任一情况立即停止当前测试：人员进入排除区；急停/使能路径未验证；运动方向、速度或
停止距离异常；无明确操作者时出现非零命令；通信或停车级输入失联；异常声响、气味、温度、
烟雾或振动；欠压、过流或保险动作；里程计/TF符号不一致；日志、设备身份或时间基线丢失。

停止后顺序为：零命令 → 急停/禁用扭矩 → 确认机械停止 → 必要时断动力 → 保存证据 → 标记
未通过 → 查明原因。不得在同一轮中边修改边继续测试。

## 9. 受控恢复

恢复前必须：确认故障原因；检查机械、电气和软件状态；确认命令为零；所有停车级输入新鲜；
人工清除ROS锁存；必要时重新上电；重新实测急停；由测试负责人和安全操作员共同确认。恢复后
从低一级门禁重新开始，不直接回到失败时的自动任务。

## 10. 证据与安全回放

每次测试记录测试ID、日期、人员、硬件/固件/驱动版本、Git提交、参数、命令、诊断、结果、
异常和签字。证据使用清单和SHA-256；原始证据访问受控，并在M8前确定保留位置、周期和容量。

rosbag只允许显式Topic白名单，禁止录制速度命令及厂商电机控制Topic；回放必须在无实体控制器
的隔离ROS Domain，或把所有控制接口重映射到不可执行名称。设备日志和MCU故障记录单独保存。

这关闭了M1～M6“大型证据保留策略未定义”的G1设计缺口；具体存储介质、备份和保留期限仍需
在M7结合组织条件落地。

## 11. 正式准入前检查

- W1仿真证据和故障注入结论可追溯；
- W2公共接口、时间、TF和安全命令链冻结；
- W3候选均有驱动路线和PoC门槛；
- W4通信、电源、算力和安装预算规则完整；
- 本W5急停、失联、限速、门禁、恢复和证据流程完整；
- 未将本方案描述为安全认证，适用法规和专业审查保留为M7硬门槛。
