# M0 开发环境与复现说明

## 支持基线

- Ubuntu 22.04
- ROS 2 Humble Desktop
- Gazebo Classic 11 与 `gazebo_ros`
- Python 3.10
- CMake 3.22 或更新版本
- `colcon`、`rosdep`

## 首次准备

安装 ROS 2 Humble Desktop 和 Gazebo ROS 集成后，初始化 `rosdep`：

```bash
sudo rosdep init
rosdep update
```

每台开发机只需执行一次 `rosdep init`。随后在仓库根目录安装工作空间依赖：

```bash
bash scripts/install_dependencies.sh
```

## 自动验证

```bash
bash scripts/check_environment.sh
bash scripts/build.sh
bash scripts/test.sh
bash scripts/check_nodes.sh
```

成功标准：

- 环境检查没有 `MISSING`；
- `colcon build` 完成全部软件包；
- `colcon test-result` 为 0 个错误和失败；
- C++ 与 Python 状态节点均收到一次预期消息。

构建产物位于 `build/`、`install/` 和 `log/`，这些目录不进入 Git。

## 人工 GUI 验证

图形程序应在桌面用户会话中验证：

```bash
source /opt/ros/humble/setup.bash
rviz2
gazebo --verbose
```

确认 RViz2 主窗口可正常显示并关闭；确认 Gazebo 能进入空世界、播放和暂停。M0 不加载
机器人模型，不发送运动指令。

## 最小软件包

| 软件包 | 类型 | 可执行程序 | 话题 |
|---|---|---|---|
| `ai_robot_cpp_demo` | `ament_cmake` | `status_publisher` | `/m0/cpp_status` |
| `ai_robot_py_demo` | `ament_python` | `status_publisher` | `/m0/py_status` |

两个软件包只用于证明 C++、Python、ROS 2 通信和测试链路可工作，不构成 M1 之后的正式
机器人接口。
