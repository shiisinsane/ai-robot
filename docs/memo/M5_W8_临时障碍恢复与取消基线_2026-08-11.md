## 5. 可复用的成功经验

### 5.1 绕行场景必须先确定相对位置

不能只按世界坐标猜测障碍是否在车前。应先读取`map → base_link`，再根据当前位置、朝向和
目标方向确定障碍坐标。最终成功场景中，小车位于`(-0.931, 0.021)`且朝正X方向，障碍预先
固定在`(0.5, 0.0)`，目标设为`(2.0, 0.0)`，从几何关系上保证障碍位于必经方向。

### 5.2 分开验证“绕行”和“动态恢复”

- 绕行验证：先放障碍、后发目标，并在导航结束前保持障碍不动，以排除障碍落在车后或
  被提前移走的歧义；
- 动态恢复验证：导航开始后再投入障碍，确认重规划或恢复已触发，再移除障碍并检查是否
  自动继续到达；
- 两类场景不能互相替代，必须分别保留结果。

### 5.3 GUI观察与机器证据要同时成立

成功不能只依据Action返回值。绕行应同时满足：用户在GUI看到小车从障碍侧面通过、障碍
始终位于小车与目标之间、机器人最终位于障碍另一侧、Action返回`SUCCEEDED`。如果GUI观察
与坐标推断冲突，以现场观察为线索重新设计确定性场景，不沿用存在歧义的结论。

### 5.4 恢复切换不能破坏安全命令契约

Nav2在控制器、等待和旋转恢复之间切换时会出现正常命令空窗。应由导航速度适配器在内部
命令新鲜时立即转发，空窗时向公共`/robot/cmd_vel`持续发送零速度心跳；不应通过放宽M4
既定的`0.2 s`超时门限规避问题。运行中还需检查安全诊断保持`ok`和`latched=false`。

### 5.5 规划失败与跟踪受阻要使用不同恢复边界

目标在地图外或不可达时，只允许清理全局代价地图后返回`ABORTED`，不得通过旋转制造无意义
运动；已有路径但跟踪受阻时，才允许清图、等待和受限旋转。这样既支持临时障碍恢复，也能
保证不可达目标失败期间没有非零运动命令。

### 5.6 推荐回归顺序

1. 确认地图、定位、规划、控制、行为服务器和BT Navigator均为活动状态；
2. 清除启动期安全锁存，并确认安全诊断正常；
3. 执行确定性静态绕行；
4. 执行行驶中投入、保持、移除障碍的动态恢复；
5. 执行公共Action取消并测量停车时延；
6. 执行不可达目标失败反馈；
7. 最后运行包测试和`git diff --check`，再更新阶段结论。

## 6. 自动定时的动态障碍GUI复验

为避免人工控制投入时机导致障碍落在车后，新增
`scripts/check_m5_dynamic_obstacle_gui.py`。脚本自行完成：读取实时`map → base_link`、发出目标、
确认机器人已经实际运动、沿机器人到目标方向计算障碍位置、校验障碍严格位于二者之间、调用
Gazebo服务投入障碍、保持障碍直到机器人完成有几何证据的侧向绕行、检查安全诊断、移回场外
并等待公共Action成功。异常退出时也会尝试把障碍回收到`(8, 8, 0.45)`。

运行时先单独启动GUI导航栈：

```bash
cd /home/yangyiyao/ai_robot
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=59
export ROS_LOG_DIR=/tmp/ai_robot_ros_logs

ros2 launch ai_robot_sim m5_recovery_navigation.launch.py \
  gui:=true \
  map:=/tmp/ai_robot_m5_w9_maps/m5_w9_runtime.yaml
```

确认Nav2节点激活后，在相同ROS域的第二个终端运行：

```bash
cd /home/yangyiyao/ai_robot
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=59
export ROS_LOG_DIR=/tmp/ai_robot_ros_logs

python3 scripts/check_m5_dynamic_obstacle_gui.py
```

修订后的默认目标为`(2.0, 0.0)`；机器人移动至少`0.15 m`后，脚本把障碍投入实时位置前方
`1.10 m`，为全局重规划和局部控制保留制动与转向空间。
障碍不再按固定时间移除：机器人中心相对投入点的最大横向位移必须达到`0.50 m`，同时纵向
位置必须越过障碍中心后方`0.45 m`安全平面，两个条件同时成立才允许移除。默认最多等待
`60 s`，未完成则保持障碍到超时、判定失败并在清理阶段回收。正式GUI复验不需要用户手动掌握
投入或移除时机。人工应确认红色障碍确实出现在运动方向前方、小车未碰撞或穿越、重新规划并
从侧面通过，随后继续到达。脚本必须同时输出投入几何证据、绕行几何证据和
“M5-W8动态障碍GUI检查通过”。

W8脚本要求公共Action返回`SUCCEEDED`且最终位置误差不超过`0.15 m`；最终航向作为观察值
记录，不在W8重复施加独立门限。精确重复到点的位置和航向门限由W9五次导航测试统一验收。

新增脚本完成无GUI运行复核：起点`(-0.000, 0.000)`，机器人运动到`(0.153, -0.003)`后，
障碍自动投入`(0.903, -0.002)`；沿目标方向投影`0.750 m`、横向偏差`0.000 m`，严格位于
机器人和`(2.0, 0.0)`目标之间。该结果属于旧版固定保持5秒的基线，只证明检测、受控响应和
移除后恢复；用户GUI复验指出障碍在清晰完成绕行前已被移除，因此不作为“障碍保持期间完成
绕行”的充分证据。修订脚本必须按上一段的双重几何门限重新取得运行结果。

修订脚本最终完成无GUI严格回归：起点`(-0.000, 0.000)`，机器人运动到
`(0.152, -0.003)`后，障碍自动投入`(1.252, -0.001)`，位于机器人前方`1.100 m`且横向
偏差`0.000 m`。障碍保持原位期间，机器人绕行至`(1.704, -0.881)`；相对投入点最大横向
位移`1.148 m`、纵向位移`1.551 m`，同时超过`0.50 m`横向净距和障碍后方`0.45 m`安全平面
门限。取得证据后障碍才移回场外，公共Action最终返回`SUCCEEDED`，终点位置/角度误差为
`0.095 m / 0.109 rad`。
