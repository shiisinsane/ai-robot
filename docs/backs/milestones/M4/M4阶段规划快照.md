## 2. 阶段目标快照

把M2底盘和M3雷达、相机、IMU、编码器组合为可统一启动、持续观察和安全停止的仿真机器人
系统；建立局部状态估计、基础感知数据链、诊断与安全监督，并验证启动顺序、时间同步、QoS、
TF完整性、资源占用、故障传播和安全停车。

## 3. 阶段范围快照

1. 完成状态估计、图像处理和诊断资源准入；
2. 冻结整机启动顺序、Topic、QoS、TF权威、超时、故障码和清除条件；
3. 建立底盘与四类传感器统一Bringup；
4. 使用编码器和IMU生成融合里程计及唯一`odom → base_link`；
5. 验证运动中的雷达、完整TF链和静态障碍物空间语义；
6. 建立相机基础校正链并保持时间戳、Frame和图像规格；
7. 建立公共命令安全监督、诊断、停车锁存及条件清除；
8. 验证实时因子、CPU、RSS、频率、QoS、时间戳和TF完整性；
9. 连续两轮隔离回归，形成最小rosbag、回放、日志、配置快照和SHA-256证据；
10. 完成正式验收、归档和阶段交接。

## 4. 冻结边界

- 公共速度命令必须经过安全监督器，控制器不直接接受公共输入；
- `/robot/odom`和`odom → base_link`由EKF唯一负责；
- 雷达、相机、IMU、关节状态和诊断保持M1公共接口契约；
- 停车级故障必须锁存，恢复需零速度、新鲜关键输入和显式清除服务；
- M4性能门限为实时因子≥0.5、CPU≤400%、RSS≤2048 MiB；
- M4不包含SLAM、地图、全局定位、Nav2、目标识别、实体机器人或AI Agent；
- M5必须由用户另行明确启动，G1和G2阶段门继续有效。
