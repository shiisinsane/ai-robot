## 总体计划中的 M0 要求

M0 只建立环境和工程基线，不接入大模型，不执行实体机器人运动。验收范围包括：

1. 核实 Ubuntu 22.04、ROS 2 Humble、磁盘、网络和代理条件；
2. 验证示例节点、`colcon`、RViz2 和 Gazebo；
3. 建立 ROS 2 工作空间、本地 Git 和统一工程目录；
4. 建立私有 GitHub 仓库、`origin`、默认分支、权限和基础保护规则；
5. 建立 README、AGENTS、忽略规则、许可证说明和三份规划基线；
6. 建立环境自检、依赖安装、构建、测试和持续集成入口；
7. 创建最小 C++、Python 节点及单元测试；
8. 建立首份第三方资源卡模板；
9. 建立 Issue、Milestone 或等价项目跟踪框架；
10. 从远程仓库全新克隆并完成依赖、构建、测试和最小节点复现；
11. 形成包含仓库地址、基线提交和复现结果的 M0 验收记录。

GitHub 部分必须具备清晰目录和安全约束，最小构建与测试能够复现，项目任务具有统一管理
入口，并且仓库不存在明文凭据、构建产物和无意提交的大文件。

## ROS 2 规划中的 M0 要求

M0 应交付：

- Ubuntu 22.04 与 ROS 2 Humble 环境自检结果；
- `colcon`、示例节点、RViz2 和 Gazebo 验证；
- 工作空间、依赖清单和统一构建入口；
- VS Code、C++、Python、CMake 与调试环境基线；
- 日志、版本、提交、文档和代理工作规则；
- 最小 C++ 与 Python ROS 2 软件包及测试；
- M0 正式验收记录。

M0 通过后才允许进入 M1“资源、接口与测试基线”。

## AI Agent 规划中的阶段边界

AI Agent 规划没有 M0 实施任务。该规划的启动条件仍为 G2 正式通过；M0 的完成不允许
提前开发或接入 AI Agent，也不允许绕过机器人能力和安全阶段门。

## 本阶段冻结结论

- 正式环境为 Ubuntu 22.04 + ROS 2 Humble；
- 仿真基线包含 Gazebo Classic 11 与 `gazebo_ros`，其后续使用或迁移在 M1 资源评审；
- C++ 与 Python 最小软件包仅证明工具链，不构成后续正式机器人接口；
- `build/`、`install/` 和 `log/` 为本地产物，不进入 Git；
- `main` 受规则集保护，后续变更通过 Pull Request 和必需状态检查；
- G1 前不进入实体机器人阶段，G2 前不启动 AI Agent 正式开发。
