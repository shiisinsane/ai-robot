# M4-W8性能与完整性验证记录

> 日期：2026年8月6日
> 结论：通过，允许进入M4-W9系统自动回归与证据

## 1. 测量范围

- 新增`check_m4_performance.py`，在不少于30秒的窗口中统一测量实时因子、整机进程树CPU、
  RSS、Topic墙钟/仿真时间频率、发布端QoS、时间戳递增及关键TF边；
- 正式环境使用独立ROS Domain和Gazebo分区，只运行一个无GUI整机实例；
- 性能门限保持W2冻结值：实时因子不低于0.5、CPU不高于400%、RSS不高于2048 MiB；
- Topic频率按M1接口契约检查，并区分墙钟接收频率与消息时间戳对应的仿真时间频率。

## 2. 审计发现与修正

### 2.1 关节状态QoS

运行端点审计发现`joint_state_broadcaster`默认以Transient Local发布`joint_states`，与公共
`state_stream`要求的Reliable + Volatile不一致。处置如下：

- 控制器改为在私有命名空间发布内部关节状态；
- 新增`joint_state_qos_adapter.py`，订阅内部Transient Local流并以Reliable + Volatile发布
  `/robot/joint_states`；
- 修正后公共Topic只有一个适配器发布者，频率和时间戳保持不变。

### 2.2 相机频率裕量

首次干净环境测量中，15 Hz仿真相机经过图像复制与校正链后，公共原始图像仿真时间接收频率
为13.573 Hz，低于15 Hz契约的95%判定线。参照M3雷达为公共频率预留处理裕量的既有策略：

- 将仿真相机内部更新率由15 Hz提高到18 Hz，不改变640×480、`rgb8`、Topic、QoS或Frame；
- 将当前传感器配置由`m3.v2`提升为`m3.v3`，历史M3归档快照不覆盖；
- 最终原始图像和校正图像仿真时间频率分别达到16.702 Hz和15.680 Hz。

并行运行用户GUI+RViz时曾测得原始图像约6.087 Hz，资源检查显示RViz单独占用约172% CPU。
该次结果被明确判为环境受污染，不用于正式验收；用户关闭旧会话后才执行最终单实例测量。
