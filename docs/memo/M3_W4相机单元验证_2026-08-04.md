# M3-W4相机单元验证记录

> 日期：2026年8月4日  
> 结论：通过，允许进入M3-W5 IMU单元

## 1. 实现范围

- 为机器人描述增加按`enable_camera`显式启用的`camera_link`、
  `camera_color_optical_frame`、固定关节和RGB相机；
- 新增独立场景`m3_camera.sdf`，在机器人前方布置红、绿色目标物；
- 新增`camera.launch.py`，独立启动Gazebo、机器人描述、桥接、适配器及可选RViz2，
  不启动底盘控制器或发布运动命令；
- Gazebo原始图像与参数分别单向桥接到`/ai_robot_internal/camera`和
  `/ai_robot_internal/camera_info`；
- `camera_driver`规范化Frame并发布M1公共接口
  `/robot/camera/color/image_raw`和`/robot/camera/color/camera_info`；
- 新增`camera.rviz`、相机适配器测试和`scripts/check_m3_camera.py`运行检查器。

## 2. 最终自动验证

无GUI隔离会话中，`scripts/check_m3_camera.py`通过全部断言：

| 指标 | 结果 | 要求 |
|---|---:|---:|
| 图像类型 | `sensor_msgs/msg/Image` | 与M1一致 |
| 参数类型 | `sensor_msgs/msg/CameraInfo` | 与M1一致 |
| 图像规格 | `640×480 rgb8` | 与W2一致 |
| 墙钟接收频率 | 13.298 Hz | ≥10 Hz，目标15 Hz |
| Frame | `camera_color_optical_frame` | 图像与参数一致 |
| 焦距 | fx=554.256，fy=554.256 | 有效正值 |
| 图像数据长度 | 921600字节 | `640×480×3` |
| 公共QoS | BEST_EFFORT、VOLATILE | `sensor_stream` |
| 光学TF旋转 | roll=-90°，yaw=-90° | REP-103光学坐标约定 |

GUI与RViz2同时运行时，受本机GPU/EGL软件渲染负载影响，首轮墙钟频率约5.409 Hz；关闭
GUI后同一相机配置恢复到约13.3～14.8 Hz。因此保留`640×480`和15 Hz参数基线，不以降低
分辨率掩盖本机图形性能问题。

包内`ai_robot_sim`最终汇总22项测试，0错误、0失败、0跳过；新增测试覆盖图像与标定消息
Frame规范化，以及公共Best Effort和RViz Reliable QoS的隔离。

## 3. 人工图形验收

用户于2026年8月4日确认：

- Gazebo GUI第三视角显示蓝色小车和前方红、绿色障碍物；
- `camera.rviz`第一视角清晰显示红、绿色障碍物；
- RViz2右侧同时显示第三视角蓝色机器人模型；
- 场景目标、相机朝向和双视角对应关系符合预期。

人工图形验收结论为成功。

## 4. 问题、修正与经验

| 问题 | 证据 | 最终处理 |
|---|---|---|
| Camera Display未订阅图像 | 初版误用`Image Topic`字段 | 按本机Humble插件格式改用Image Display和`Topic`字段 |
| RViz订阅存在但无画面 | 日志明确报告`RELIABILITY_QOS_POLICY`不兼容 | 不修改公共QoS，增加仅供RViz使用的Reliable镜像话题 |
| 旧示例插件名无法加载 | `rviz/Image`未注册 | 使用本机已注册的`rviz_default_plugins/Image` |
| GUI并行运行帧率下降 | GUI约5.409 Hz、无GUI约13.298 Hz | 自动频率验收使用隔离无GUI会话，GUI只验证视觉语义 |

关键经验如下：

1. RViz配置必须以目标ROS 2发行版实际注册的插件类和属性为准，不能只依据其他版本示例；
2. “Topic存在”和“订阅者存在”不代表能够通信，必须检查双方QoS及运行日志；
3. M1冻结的公共传感器接口优先级高于调试工具兼容性。可视化适配应放在非公共调试话题，
   不得静默改变业务QoS；
4. 图形人工验证和无GUI自动性能验证应分开：前者验证内容、方向和视场，后者验证消息规格、
   Frame、CameraInfo和频率；
5. 每次修改RViz配置后必须重新构建安装并重启RViz，否则容易误判仍在加载旧配置。
6. 本轮“Gazebo GUI与RViz2同时启动”只证明静态相机场景能够完成视觉验收，不应推广为
   带模型生成、控制器和动作测试的默认启动顺序。后续W5已验证：高负载动态GUI应先无界面
   初始化服务端，再以相同`IGN_PARTITION`接入GUI客户端；该流程与本节的性能/视觉分离原则
   一致，不改变W4的相机QoS、图像内容和Frame结论。

## 5. 边界与下一入口

- W4未实现图像识别、目标检测、深度相机或多传感器融合；
- 未启动底盘运动，未连接实体设备或AI Agent；
- Reliable镜像`/ai_robot_visualization/camera/image_raw`只服务RViz调试，不属于M1公共接口；
- M1公共相机Topic、消息、命名、Frame和Best Effort QoS均未改变。

下一入口为M3-W5 IMU单元；M3正式验收通过前不得进入M4。
