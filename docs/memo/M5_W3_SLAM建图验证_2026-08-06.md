## 3. GUI人工复核步骤

当前可靠流程采用“服务端先启动、RViz后接入”，不要在M5-W3使用单条Launch命令同时启动
Gazebo和RViz。终端一启动Gazebo、机器人和SLAM：

```bash
cd /home/yangyiyao/ai_robot
source install/setup.bash
ros2 launch ai_robot_sim m5_slam.launch.py gui:=true rviz:=false
```

确认Gazebo中小车生成后，终端二单独启动RViz：

```bash
cd /home/yangyiyao/ai_robot
source install/setup.bash
rviz2 -d src/robot_core/ai_robot_sim/config/slam_mapping.rviz
```

RViz固定坐标应为`map`，应看到灰色未知区、白色自由区、黑色墙体、机器人模型和红色雷达点。
若左侧配置区未出现，使用`Panels → Add New Panel → Displays → OK`。TF中应存在且只存在一条
`map → odom → base_link → laser_link`主链。

终端三执行自动闭环路线：

```bash
cd /home/yangyiyao/ai_robot
source install/setup.bash
python3 scripts/run_m5_slam_route.py
```

观察要求：机器人连续完成四次直行和左转；地图随运动扩展，四面墙连续，两个内部地标可区分；
机器人模型、雷达点和地图保持对齐，不出现地图整体跳跃、双影、TF红色报错或穿墙。脚本输出
“方形闭环路线完成”后机器人应停止。最后在终端一按`Ctrl+C`关闭。

## 4. GUI人工验证结果

用户按“Gazebo/SLAM服务端、RViz客户端、路线脚本”三个终端完成从头复验。Gazebo中小车生成、
运动和转弯均顺滑；RViz中运行轨迹正确，地图扫描区域随运动正常变化，但RobotModel坐标存在
轻微跳摆。由于Gazebo物理运动顺滑且RViz地图、轨迹、TF没有整体跳跃、明显双影、穿墙、红色
错误或路线中断，本次现象判定为`map → odom`扫描匹配修正叠加融合里程计小幅波动，而非底盘
机械或控制抖动，作为可接受基线保留。W5定位稳定性测试需继续量化静止位姿抖动；若出现持续
摆动、地图错位或厘米级以上跳跃则重新调查，不把本次结论直接外推到AMCL定位模式。

### 4.1 启动经验与文档一致性检查

- M5-W3原记录中的单命令`gui:=true rviz:=true`与实测矛盾，现已替换，不再作为有效步骤；
- 实测中组合启动曾出现RViz未启动；尝试隔离Launch参数后又触发`world_name`配置缺失，导致整个
  Launch关闭、RViz闪退且小车未生成，该尝试已由用户撤销；
- 当前冻结的可靠方式是先以`rviz:=false`启动Gazebo、机器人和SLAM，确认小车生成后再单独启动
  RViz，最后执行路线脚本；
- 该经验与`M3_W5_IMU单元验证_2026-08-04.md`中的“服务端先行、GUI/RViz后接入”结论一致，
  也符合M4遗留问题中GUI调试与性能测量分离的要求；未发现与正式规划或接口规范冲突。

## 5. 边界与下一入口

W3证明在线建图、公共Topic、运行频率和TF链有效，但尚未证明地图文件可安全保存、完整重载或
用于定位。W4将实现`SaveMap`公共Service、路径约束、地图文件完整性与重载一致性检查。
