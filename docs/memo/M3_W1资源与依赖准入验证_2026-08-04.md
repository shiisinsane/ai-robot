# M3-W1资源与依赖准入验证记录

> 日期：2026年8月4日  
> 结论：通过，允许进入M3-W2参数与TF基线

## 1. 锁定资源

| 资源 | 锁定版本 | 许可证 | 用途 |
|---|---|---|---|
| Gazebo Fortress | 6.18.0 | Apache-2.0 | M3～M6仿真平台 |
| Ignition Sensors | 6.9.0 | Apache-2.0 | GPU Lidar、Camera和IMU仿真 |
| `ros_gz` | 0.244.25 | Apache-2.0 | Gazebo Transport与ROS 2桥接 |
| `sensor_msgs` | 4.9.1 | Apache-2.0 | ROS 2标准传感器消息 |
| `image_transport` | 3.1.13 | BSD | 原始图像及派生传输 |

独立资源卡位于`../../resources/`。M3继续采用M1确定的Fortress主线，不切换Gazebo Classic。

## 2. 本机静态检查

- camera、gpu-lidar、imu传感器库和Fortress Sensors/IMU系统插件存在；
- `ros_gz_bridge`、`ros_gz_image`、`ros_gz_sim`和官方传感器demos可被ROS 2发现；
- `sensor_msgs/msg/LaserScan`、`Image`、`CameraInfo`和`Imu`均可解析；
- 桥接共享库包含四类Gazebo与ROS 2消息的转换工厂；
- M1接口契约已定义对应Topic、消息类型、最低频率、超时和QoS配置档。

## 3. 动态消息桥接验证

使用独立`ROS_DOMAIN_ID=75/76`和独立Gazebo Transport分区，不启动项目机器人、不发送运动
命令。通过`ign topic`发布确定的Gazebo测试消息，由`parameter_bridge`转换并使用
`ros2 topic echo --once`接收。

| 接口 | Gazebo消息 | ROS 2结果 | 结论 |
|---|---|---|---|
| 测试雷达 | `ignition.msgs.LaserScan` | Frame为`laser_link`，角度、量程、3点距离和强度保留 | 通过 |
| 测试图像 | `ignition.msgs.Image` | `1×1`、`rgb8`、步长3 | 通过 |
| 测试相机参数 | `ignition.msgs.CameraInfo` | `640×480`、`plumb_bob` | 通过 |
| 测试IMU | `ignition.msgs.IMU` | ROS 2 `sensor_msgs/msg/Imu`收到角速度和线加速度 | 通过 |

以上只证明资源、类型和转换链可用，不证明项目传感器参数、频率、噪声、时间戳或Frame已经
通过验收。

## 4. 已知风险与后续边界

- 用户确认官方GPU Lidar示例的“游乐场”设施世界已在Gazebo GUI中正常显示；这证明GUI
  世界加载和可视渲染路径可用，但不等于雷达数据已经验证；
- 后续强制使用服务端无界面模式时，本机NVIDIA/EGL未能创建OGRE2渲染上下文并退出，桥接
  节点则正常创建。W3和W4仍须分别验证实际传感器数据及可重复的无界面回归路径；
- Gazebo IMU消息不直接携带ROS协方差，W2需冻结协方差值和适配责任；
- 首版M3只要求RGB相机；深度图像仍是M1条件接口；
- 项目桥接配置应只开放Gazebo到ROS 2方向，避免反向发布进入传感器数据源；
- `camera_info_manager`当前未安装，仿真相机桥接不依赖它；若后续需要外部标定文件再准入。

M3-W1通过。资源来源、版本、许可证、接口影响、最小动态验证、风险和回退方案均已记录。
