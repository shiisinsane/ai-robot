# 第三方资源卡

本目录保存候选第三方资源的准入记录。M1 开始后，每项正式候选资源应基于
`资源卡模板.md` 创建独立资源卡。

资源卡用于记录来源、版本、许可证、维护状态、ROS 2 Humble 兼容性、接口影响、测试证据
和回退方法。资源卡不代替源码许可证，也不表示候选资源已经获准进入稳定基线。

## 目录文件

- `M1对象与资源矩阵.md`：记录对象职责、候选资源、仿真与实体实现、接口输入和测试方法；
- `资源卡模板.md`：每个正式候选资源的独立审查模板；
- `robot_state_publisher_3.0.3.md`、`xacro_2.1.1.md`：M2模型与TF资源；
- `gz_ros2_control_0.7.20.md`：Fortress控制集成资源；
- `ros2_controllers_2.53.1.md`、`diff_drive_controller_2.53.1.md`：M2控制器资源；
- `ignition_sensors_6.9.0.md`：M3雷达、相机和IMU仿真传感器资源；
- `ros_gz_0.244.25.md`：M3 Gazebo Transport与ROS 2消息桥接资源；
- `image_transport_3.1.13.md`：M3图像传输与派生传输资源；
- `robot_localization_3.5.4.md`：M4编码器与IMU局部状态估计候选资源；
- `image_proc_3.0.9.md`：M4 RGB基础图像处理候选资源；
- `diagnostic_updater_4.0.7.md`：M4标准诊断发布候选资源；
- 后续资源卡：按`资源名称_版本或发行版.md`命名，避免使用含义不明的“最新版”。

## 准入状态

```text
待调研
→ 候选
→ 验证中
├── 已准入
├── 已拒绝
└── 延期
```

- `待调研`只在对象矩阵中使用，表示尚未创建完整资源卡；
- `候选`表示资源已进入正式审查；
- `验证中`表示正在执行兼容性、接口或最小样例验证；
- `已准入`必须具有锁定版本、通过标准、验证结果、证据位置和回退方法；
- `已拒绝`必须记录原因和替代方案；
- `延期`必须记录重新审查条件。

## 准入流程

1. 从对象矩阵识别需要正式比较的候选资源；
2. 复制模板并填写来源、版本、许可证、维护状态和兼容性证据；
3. 核对接口、QoS、TF、时间戳、参数、资源占用和安全影响；
4. 在Ubuntu 22.04与ROS 2 Humble基线上执行可重复的最小验证；
5. 保存命令、配置、结果、证据位置、已知问题和回退方法；
6. 根据证据标记为已准入、已拒绝或延期，并同步更新对象矩阵；
7. 资源升级或公共接口变化时重新执行契约与相关回归测试。

原则上不直接修改第三方源码。优先使用配置、适配器或薄封装；确需补丁时，应记录
上游版本、补丁原因、差异、测试和回退方式。
