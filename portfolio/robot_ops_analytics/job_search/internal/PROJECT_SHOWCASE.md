## 项目产出

我完成的不是一个只展示模型分数的Notebook，而是一套可审计、可复现的机器人运营分析系统：

它要解决的运营问题是：固定超时规则无法区分复杂但正常的慢任务与真正异常，容易造成误报或延迟
升级。项目通过可信任务基线，为差异化任务预算、异常升级、容量规划和路线选择提供决策依据。

| 产出 | 已完成结果 | 解决的问题 |

## 我具体做了什么

这是个人独立完成的端到端项目，我负责：

1. 把机器人运行问题定义成任务粒度的业务问题，冻结KPI、过滤规则和安全护栏。
2. 设计任务、事件、遥测与实验维度Schema，并记录从原始字段到分析指标的数据血缘。
3. 编写Python采集、ETL、质量审计和实验编排程序，构建SQLite事实层与DuckDB/Parquet分析出口。
4. 编写SQL完成KPI、周期长尾、失败场景、阶段和安全分析，并用独立Python实现逐项对账。
5. 发现初版实验存在路线长度、障碍位置和端点几何混杂，主动否定过强的早期结论。
6. 重新设计并执行预注册平衡区组实验，使用10,000次bootstrap报告效应及95%区间。
7. 保存配置、版本、白名单、无效样本和验收记录，使每个数字都能追溯到运行证据。

## 我构建的指标体系

我不是拿到现成KPI后做报表，而是先把“机器人运行得好不好”拆成可计算的问题：

- **总目标：**在安全不变差的前提下，提高每台机器人单位仿真时间内完成的有效任务数。
- **完成能力：**任务完成率、准时完成率、失败率和恢复/介入率。
- **周转效率：**任务周期P50/P90/P95、阶段耗时和路径效率。
- **问题定位：**按定位、规划、控制、感知和安全阶段拆解失败。
- **安全与质量护栏：**安全停车率、传感器过期任务率、超速任务率和有效遥测覆盖率。

每个指标都定义了统计对象、分子、分母、过滤条件、时间口径、分组维度、空值处理和适用限制。
例如，任务完成率只统计“有效且已被系统接受”的任务；拒绝和取消单独报告，避免通过拒绝困难任务
人为抬高完成率。正式耗时使用ROS仿真时间，不能与环境启动或墙钟时间混算。效率指标必须和安全
护栏一起看，避免机器人为了更快而牺牲安全。

## 最有价值的分析判断

早期81次探索任务中有15次失败，SQL把异常定位到固定的
`return_home + medium obstacle`场景。随后30次单变量实验出现low组0/15失败、medium组15/15
失败——这是一个非常适合写进“玩具项目”的漂亮数字。

但我进一步审计发现，旧路线只有0.4～0.8米，障碍同时靠近路线和端点，障碍难度、路线长度与
端点几何效应没有分开。因此我没有把“100%对0%”包装成普遍因果结论，而是保留原始结果、指出
混杂，并重做实验设计：统一4米路线和起终点，仅改变障碍档位，采用15个三臂平衡随机区组。

正式实验结果如下：

| 比较 | 周期中位数差及95% bootstrap区间 | 最大横向偏移中位数差及95%区间 |
|---|---:|---:|
| low - none | +21.511秒 `[17.790, 26.816]` | +0.341米 `[0.313, 0.359]` |
| medium - none | +27.165秒 `[21.058, 33.740]` | +1.012米 `[0.999, 1.014]` |

三组均15/15成功，必需遥测覆盖率100%，安全停车和传感器过期任务均为0。因此结论是“当前仿真
配置下障碍稳定增加耗时和绕行”，而不是“障碍导致失败”。每组0/15失败的Wilson 95%区间上限
仍为20.39%，现有数据也不足以宣称失败风险为零或训练可靠的失败预测模型。

由于原预注册bootstrap没有保留15个随机区组的配对结构，我另外进行了明确标记为事后的block
bootstrap和区组内精确随机化检验。四项区间均未跨0，结论方向保持一致；medium周期的区组
bootstrap区间为`[20.946, 36.750]`秒，显示不确定性比原分析略大。

## 为什么它不是学校玩具项目

| 常见课堂项目 | 本项目 |
|---|---|
| 下载一份已清洗CSV | 从ROS 2任务、事件、遥测与实验配置开始定义数据契约 |
| 只保留可用样本 | 无效尝试进入隔离区，原因和批次仍可审计 |
| Notebook里一次性清洗 | 版本化ETL、质量门禁、Schema测试和可重复运行入口 |
| 随机拆分后追求最高分 | 明确决策时点，规划按完整实验区组切分以防近重复泄漏 |
| 展示相关性或单个p值 | 预注册实验、混杂审计、效应量、区间和停止规则同时报告 |
| 只报提升，不报限制 | 明确区分探索、验证和正式数据，不外推实体或生产收益 |
| 指标无法追溯 | 39项SQL/Python对账，每条简历陈述映射到证据文件 |

它的价值不在于数据规模巨大，而在于把真实数据工作的关键难题做完整：数据是自己产生的、口径会
漂移、实验会混杂、运行会失败、结果可能不支持原假设，而最终结论仍必须可复算、可解释、可审计。
