# G1-W3硬件与驱动候选审查

> 日期：2026年8月13日
> 结论：条件通过
> 资料核对日期：2026年8月13日

## 1. 审查结论

已为底盘/MCU、电机驱动、编码器、二维雷达、RGB/深度相机和IMU建立可进入M7 PoC的候选
路线。候选均可通过G1-W2适配边界提供冻结公共接口，未发现必须修改`m1.v2`的硬件依赖。

本阶段不冻结最终型号。项目尚缺预算、采购地区、整机质量与载荷、轮径和轮距、机械安装空间、
电池电压与容量、板载算力和环境等级；在这些输入确定前，任何单一型号都只能是候选，不能形成
采购决定。

## 2. 候选总表

| 对象 | 主候选路线 | 备选路线 | 当前判定 |
|---|---|---|---|
| 底盘控制 | 差速底盘＋编码电机＋MCU闭环＋`ros2_control SystemInterface` | MCU串口/CAN薄适配节点 | 架构准入，型号待约束 |
| MCU | STM32级MCU，FreeRTOS或裸机安全环，CAN/UART到上位机 | 支持micro-ROS的MCU/RTOS组合 | 条件准入，安全功能不得依赖DDS |
| 电机驱动 | 具备硬件使能、过流/过温保护和故障输出的双通道驱动 | 两个独立驱动器＋统一MCU闭环 | 条件准入，电压电流待核算 |
| 编码器 | 双轮增量式正交编码器，MCU硬件计数 | 电机驱动器内置编码反馈 | 条件准入，分辨率待运动预算 |
| 二维雷达 | SICK兼容设备＋`sick_scan_xd` | YDLIDAR＋`ydlidar_ros2_driver`；RPLIDAR需先确认ROS 2分支 | 主/备候选形成 |
| RGB/深度相机 | RealSense系列＋`realsense2_camera` | Orbbec Gemini系列＋`OrbbecSDK_ROS2` | 主/备候选形成 |
| IMU | MicroStrain G/C系列＋官方ROS 2驱动 | Bosch BMI08x级器件＋MCU采集和自研薄适配 | 主/备候选形成 |

“主候选”表示驱动成熟度和可追溯性优先，不代表成本、供货或机械条件已经最优。

## 3. 底盘、MCU、电机驱动和编码器

### 推荐架构

```text
ROS 2安全过滤后的/controller_cmd_vel
→ ros2_control SystemInterface或薄底盘适配器
→ CAN/UART带序号、心跳和CRC的MCU协议
→ MCU双轮速度闭环
→ 电机驱动器

编码器/驱动故障/电池状态
→ MCU
→ 原始轮状态、里程计和诊断
→ 实体适配器与robot_localization
→ /robot/joint_states、/robot/odom、/robot/battery_state
```

ROS 2 Humble 的`ros2_control`官方文档提供硬件组件与`SystemInterface`，其生命周期包含初始化、
配置、激活、停用、读和写，适合把实体底盘封装在已验收的控制器体系下：
[ros2_control Humble文档](https://control.ros.org/humble/doc/ros2_control/doc/index.html)。

micro-ROS可作为MCU通信候选，但只用于命令和状态传输；急停、命令失联停车、电机使能和基本
限速必须在MCU/硬件侧独立成立，不能依赖Agent、DDS或上位机存活。由于micro-ROS方案会增加
RTOS、Agent和DDS-XRCE运维面，默认优先“明确版本的自定义CAN/UART协议＋ROS 2薄适配器”，
只有需要MCU直接发布多类ROS消息时才进入micro-ROS PoC。

### 淘汰条件

- 驱动器没有独立硬件使能或故障输出；
- MCU失联后不能在确定时限内令速度目标归零并关闭电机输出；
- 编码器分辨率、采样率或方向不能满足20 Hz公共里程计和50 Hz状态估计输入；
- 驱动协议无帧校验、序号/时间、超时和明确错误码；
- 必须绕过`/robot/cmd_vel`安全链才能工作；
- 只能由root权限或不可审计的常驻厂商工具控制。

## 4. 二维雷达候选

### 主候选：SICK兼容二维设备

SICK官方`SICKAG/sick_scan_xd`支持ROS 2，并提供Ubuntu 22.04/Humble二进制安装路径
`ros-humble-sick-scan-xd`，同时包含诊断、时间同步、仿真和单元测试说明：
[sick_scan_xd官方仓库](https://github.com/SICKAG/sick_scan_xd)。

准入优点：官方维护、Humble路径明确、Ethernet设备便于固定拓扑和诊断。代价通常是成本和
体积较高，具体设备仍需按量程、视场、扫描频率、防护等级和安装空间筛选。

### 备选：YDLIDAR；RPLIDAR待分支核验

YDLIDAR官方ROS 2驱动提供`humble`分支，输出标准`LaserScan`，可作为低成本串口备选：
[ydlidar_ros2_driver官方仓库](https://github.com/YDLIDAR/ydlidar_ros2_driver)。M7必须固定SDK和
驱动提交，验证自动重连、设备别名、时间戳、角度方向和10 Hz以上稳定输出。

SLAMTEC公开SDK持续维护，但检索到的`rplidar_ros`默认说明仍以catkin/ROS 1命令为主，因此
不能仅凭仓库存在判定Humble准入：[RPLIDAR官方ROS仓库](https://github.com/Slamtec/rplidar_ros)。
若选RPLIDAR，M7必须先确认官方ROS 2分支、目标型号、许可证和Humble构建/运行结果。

### 雷达PoC门槛

- 输出可适配为`/robot/scan`、`sensor_msgs/msg/LaserScan`、Best Effort、`laser_link`；
- 稳定频率不低于10 Hz，断流在0.5秒门限内被安全链检测；
- 角度递增、最小/最大量程、NaN/Inf表达和时间戳符合契约；
- USB或Ethernet重连后不静默改变设备身份、Frame或扫描方向。

## 5. 相机候选

### 主候选：RealSense

RealSense官方ROS封装明确列出Ubuntu 22.04上的ROS 2 Humble，并提供
`ros-humble-realsense2-*`安装方式：[RealSense ROS官方说明](https://github.com/realsenseai/realsense-ros/blob/ros2-master/README.md)。
Humble发布仓库记录了`realsense2_camera`、消息和描述包的正式发布：
[RealSense Humble发布记录](https://github.com/IntelRealSense/realsense-ros-release)。

适合需要RGB并保留未来深度能力的路线；必须核对目标算力平台上的USB 3带宽、SDK/内核组合、
设备温度、时间同步和长期供货。

### 备选：Orbbec Gemini系列

Orbbec官方ROS 2 Wrapper声明支持Humble，提供`ros-humble-orbbec-camera`二进制包，并给出不同
设备应选`main`或`v2-main`分支的维护矩阵：
[OrbbecSDK_ROS2官方仓库](https://github.com/orbbec/OrbbecSDK_ROS2)。必须按具体型号冻结分支，
不能把同一品牌下所有相机视为同一兼容性。

### 相机PoC门槛

- RGB必须适配为`640×480 rgb8`或经明确转换得到该公共基线，频率不低于15 Hz；
- 图像和`CameraInfo`时间戳、Frame、内参和畸变模型一致；
- 公共QoS为Best Effort，厂商服务和私有Topic不泄漏给应用层；
- 深度接口只在硬件和带宽验证通过后从“条件”启用；
- 录包、回放和并行Nav2负载下无不可接受的USB丢帧或内存增长。

## 6. IMU候选

### 主候选：MicroStrain G/C系列

MicroStrain官方仓库包含ROS 2分支和设备驱动包，覆盖当前G/C系列：
[microstrain_inertial官方仓库](https://github.com/LORD-MicroStrain/microstrain_inertial)。该路线
时间戳、协方差和诊断能力较完整，适合降低自研驱动风险，但成本和体积需结合整机约束评估。

### 备选：Bosch BMI08x级器件＋MCU适配

Bosch官方维护BMI08x Sensor API，可作为板载低成本IMU基础：
[Bosch Sensortec官方组织与BMI08x API](https://github.com/boschsensortec)。它不是现成ROS 2
驱动，因此必须由MCU采样并由上位机薄适配器补齐时间戳、ENU坐标、协方差、诊断和标定。
如器件不直接输出姿态，可使用Humble的`imu_filter_madgwick`候选，但最终局部状态仍由
`robot_localization`统一融合：[imu_filter_madgwick Humble文档](https://docs.ros.org/en/humble/p/imu_filter_madgwick/)。

### IMU PoC门槛

- 输出`/robot/imu/data`、`sensor_msgs/msg/Imu`、`imu_link`，频率不低于50 Hz；
- 明确原始坐标是ENU、NED还是NWU，并在适配层转换为REP-103/项目约定；
- 协方差不能伪造为全零，时间戳不能使用接收线程的无界延迟时间；
- 断流在0.2秒内触发停车级故障；静止、旋转符号、温漂和启动偏置均需实测。

## 7. 版本、许可证与维护要求

- M7必须记录具体硬件料号、固件、SDK、驱动分支/标签/提交、许可证和Ubuntu/Humble组合；
- 优先使用官方二进制包或官方仓库；社区Fork只能作为有明确维护责任人的回退；
- 不直接修改第三方源码，优先参数、Launch、重映射和薄适配；必须补丁时单独维护并记录上游差异；
- 任何云端依赖、闭源运行时、内核模块或root权限要求都必须在M7风险表中单列；
- 候选在M7完成离线构建和接口PoC，在M8完成单设备实体测试后才能正式定型。

## 8. 尚需用户输入的选型约束

| 约束 | 对候选的影响 |
|---|---|
| 采购地区与预算范围 | 决定工业级与低成本雷达、工业IMU与板载IMU的权衡 |
| 整机质量、载荷、最高速度和坡度 | 决定电机扭矩、减速比、驱动电流和制动需求 |
| 轮径、轮距和底盘外形 | 决定编码器分辨率、控制参数和雷达视野遮挡 |
| 电池电压、容量和续航目标 | 决定驱动器、DC-DC、保险和峰值功率预算 |
| 上位机型号、CPU/GPU和接口数量 | 决定相机分辨率、USB带宽及感知扩展能力 |
| 室内/室外、粉尘、光照和温度 | 决定雷达、相机、IMU防护和环境等级 |
| 是否需要深度相机 | 决定条件深度接口是否启用及带宽预算 |

这些约束不阻止G1继续做架构准入，但G1-W6只能给出“允许进入M7完成最终定型”的结论，不能
声称具体采购型号已冻结。

## 9. 下一入口
