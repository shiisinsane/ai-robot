## 1. 业务目标

围绕“在不恶化安全护栏的前提下，提高单位仿真时间内的有效完成任务数”开展分析。W6不以输出
更多图表为目标，而是回答三个决策问题：

1. 当前任务完成能力和周转效率处于什么水平？
2. 失败与长耗时主要由哪些路线、障碍和初始位姿扰动组合贡献？
3. 哪些异常值得预注册补采或控制变量实验，未来可转化为任务前检查、重定位或参数策略？

## 2. 分析原则

- 全部正式结果只使用W5白名单内81项自然运行任务；
- 每个分组必须同时报告样本数、成功数、失败数和失败贡献度；
- 失败率描述组内风险，失败贡献度描述该组占全部失败的比例，二者不混用；
- P50/P90/P95使用ROS仿真时间的任务周期，不使用墙上时间；
- 任务级指标从任务事实表计算；跨事件和遥测事实时先预聚合，禁止直接`COUNT(*)`计算任务数；
- SQL发现只表述相关性。因果结论必须由预先登记的控制变量实验支持；
- 81项为探索基线，不外推真实机器人运营故障率，也不作为冻结模型测试集。

## 3. 第一轮业务问题与输出

| 编号 | 业务问题 | 核心输出 | 决策用途 |
|---|---|---|---|
| Q1 | 整体完成能力如何？ | 任务数、成功/失败数、完成率 | 建立基线，防止只展示成功样本 |
| Q2 | 周转效率与长尾如何？ | 周期均值、P50/P90/P95，按终态对比 | 判断吞吐受典型任务还是长尾拖累 |
| Q3 | 失败集中在哪里？ | 按路线、障碍、扰动分组的样本量、失败率、失败贡献度 | 确定优先排查场景 |
| Q4 | 哪些组合同时高失败和长耗时？ | 场景组合二维排序及最小样本标记 | 选择补采而非追逐偶然极值 |
| Q5 | 失败前经历了什么？ | 阶段序列、各阶段停留、终态前窗口 | 形成机制假设 |
| Q6 | 失败前遥测有何差异？ | 早期/终态前速度、障碍距离、传感器与安全状态 | 判断候选预警特征 |
| Q7 | 安全和数据质量护栏如何？ | 最小障碍距离、停车任务率、过期掩码、覆盖率 | 防止用安全恶化换效率 |
| Q8 | 是否存在连续失败或批次聚集？ | 按墙上启动顺序的失败段和场景 | 区分场景问题与环境时段问题 |

## 4. SQL执行顺序

SQL清单冻结在`sql/README.md`，按以下顺序实施：

```text
数据契约复核
  → 整体KPI与周期分位数
  → 场景分组与失败Pareto
  → 阶段时长与终态前遥测
  → 安全护栏与连续失败
  → 异常候选及补采决策
```

每条核心SQL必须包含用途、输入粒度、过滤条件、输出粒度和限制说明，并能在DuckDB中独立执行。

## 5. 当前可用与不可用指标

### 可正式计算

- 任务完成率、失败率和失败贡献度；
- 任务周期均值及P50/P90/P95；
- 路线、障碍难度、初始位姿扰动和参数版本分组；
- 阶段事件数量、顺序和近似停留时间；
- 最大速度、最小有效雷达距离、安全停车、传感器过期及遥测覆盖；
- 成功与失败任务的上述指标差异。

### 只能探索或暂不可用

| 指标 | 状态 | 原因或处理 |
|---|---|---|
| 单位机器人小时有效任务数 | 暂不可正式计算 | 当前分析层没有冻结的机器人Ready运行窗口事实 |
| 准时完成率 | 仅候选分析 | SLA尚未冻结；W6只能提出候选值，不能追溯调优 |
| 恢复/介入率 | 暂不可用 | 当前记录没有可靠恢复或明确介入事件 |
| 路径效率 | 暂不可用 | 缺少冻结规划路径长度与可靠实际路径累计 |
| 真实人工介入率 | 禁止使用 | 没有真实人工操作事件 |
| 自然运营故障率 | 禁止外推 | 数据来自受控仿真矩阵 |

缺失指标不使用默认值填充，也不以“0”替代不可观测状态。

## 6. 异常晋级与补采门禁

一个发现只有同时满足以下条件才进入补采候选：

1. SQL和数据版本可复现；
2. 报告分组样本量、失败率、失败贡献度和效应方向；
3. 不是由单个任务、Join膨胀或数据质量异常造成；
4. 能提出可证伪的机制假设；
5. 可以只改变一个主要因素设计控制变量实验。

补采前必须另行登记路线、障碍、扰动、样本数、停止条件和主要/护栏指标。未登记前不启动新的
Gazebo采集，也不根据结果好坏选择性补样本。
