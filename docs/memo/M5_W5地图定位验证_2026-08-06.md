# M5-W5地图定位验证记录

> 日期：2026年8月6日，2026年8月11日完成补充验证
> 状态：已完成，允许进入M5-W6全局规划。

## 已完成基线

- Map Server加载W4地图，AMCL独占`map → odom`，定位Launch中不启动SLAM；
- `/robot/initialpose`输入和`/robot/pose`输出有效；
- 首轮自动检查采集6条位姿和480条TF样本，静止位置抖动`0.0032 m`，低于`0.03 m`门限；
- 用户在GUI验证中发现默认ROS域混有外骨骼、MoveIt、全局控制器和多个同名
  `robot_state_publisher`，曾导致节点图警告、TF黄色和安全停车；
- 三个终端统一设置独立`ROS_DOMAIN_ID=157`后，Gazebo、RViz和方形回环路线恢复正常。
- 用户进一步确认运动结束后Gazebo中的真实位置与RViz中的AMCL估计位置一致；虽然开环方形路线
  未精确回到起点，但未观察到定位结果相对真实位置的明显偏移。因此当前运动对齐检查通过，
  终点回环误差归因于定时路线自身，不作为W5定位精度失败。

## 人工验证冻结经验

Gazebo/定位Launch、RViz和路线脚本必须在每个终端`source install/setup.bash`后设置相同、独立的
`ROS_DOMAIN_ID`。启动后先确认项目命名空间下的controller manager、差速控制器、EKF、IMU、
robot state publisher、AMCL和Map Server全部存在，再发送运动命令。

当前`run_m5_slam_route.py`是开环定时路线：四次固定时长直行与转弯只形成近似方形回环。理想的
瞬时、无滑移模型会接近起点，但实际存在加减速限制、控制周期、轮地滑移、转角误差和停车超时，
误差会逐段累积。脚本不读取`odom`或AMCL位姿来修正边长、转角或终点，因此未回到起点不表示
AMCL定位失败，也不能把该脚本称为位置闭环控制。精确回点属于后续Nav2控制与到点精度验收。

W5关注“估计位置是否跟随真实位置且雷达与地图保持对齐”，不要求开环测试路线返回起点；W6～W7
将使用规划与反馈控制验证目标到达和`0.15 m`到点门限。

## 2026年8月11日补充验证

将运行检查扩展为带冻结初始偏差的收敛、受监督低速运动、静止抖动、TF持续性和
异常初始位姿检查。临时地图通过W3方形路线重新生成并保存到
`/tmp/ai_robot_m5_w5_maps`，不纳入Git。所有终端使用`ROS_DOMAIN_ID=157`。

运行结果：

```text
M5-W5定位检查通过
- 冻结初始偏差：(0.20, -0.10, 0.10 rad)
- 收敛误差：位置0.096 m，角度0.010 rad
- 样本：位姿6条、里程计753条、TF 1901条；静止抖动0.0000 m
- 非map初始位姿被拒绝后，既有定位输出和TF保持有效
```

地图缺失负向测试中，Map Server在`configure`转换时明确报告文件不存在，Lifecycle
Manager报告无法启动全部受管节点并终止bringup；AMCL未进入活动定位状态，符合
`map_missing: lifecycle_activation_failure`的失败关闭约定。

## 结论与边界

W5所需的静态定位、冻结初始偏差收敛、运动跟随、异常输入和缺失地图失败关闭已完成。
该结论不代替W6～W7的Nav2规划、反馈控制和到点精度验收，也不将定时方形路线表述为
位置闭环控制。W5结论为“通过”，下一入口为M5-W6全局规划；本次未进入W6实施。
