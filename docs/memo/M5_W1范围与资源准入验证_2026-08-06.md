# M5-W1范围与资源准入验证记录

> 日期：2026年8月6日
> 结论：通过，允许进入M5-W2导航契约与依赖基线

## 1. 输入基线

- M4于2026年8月6日正式验收并归档，统一Bringup、EKF、雷达、相机和安全监督可用；
- `map → odom`尚不存在，M4冻结的`odom → base_link`继续由状态估计器唯一发布；
- M1已冻结`SaveMap`、`NavigateToPose`和`FollowWaypoints`接口名称与类型；
- 所有导航速度必须进入`/robot/cmd_vel`，再经过M4安全监督和过滤链到达底盘；
- M4正式证据基线为提交`6010ed4`，工作区启动M5前为干净状态。

## 2. 范围结论

M5交付二维SLAM、地图保存/重载、地图定位、Nav2规划与控制、静态/临时障碍处理、恢复、取消、
不可达反馈、导航安全性能和自动证据。M5不包含实体机器人、AI Agent、三维或视觉SLAM、目标
识别、语义导航，也不提前执行M6综合能力验收。

## 4. 关键架构风险

1. SLAM和AMCL/定位模式都可能发布`map → odom`，W2必须冻结按模式互斥的唯一权威；
2. Nav2 Controller默认发布速度命令，必须重映射到M4公共安全入口，禁止连接
   `/robot/safety_cmd_vel`或`/robot/controller_cmd_vel`；
3. M4只验证传感器断流，不等于检测到障碍物就会停车；M5必须通过代价地图和局部控制器验证
   静态/临时障碍行为；
4. 地图、定位和代价地图对TF时间、激光频率、机器人外形与膨胀半径敏感，不能以“节点启动”
   代替地图质量和导航成功率；
5. GUI与性能测量并行会显著争用渲染资源，自动性能验收继续使用单实例无GUI环境。

## 5. 回退边界

- SLAM失败时停用建图节点，保留M4局部`odom`运动与感知；
- 定位失败时停止Nav2生命周期节点，不允许盲目继续目标导航；
- Planner或Controller失败时取消任务并由M4安全监督停车；
- 不修改第三方源码，优先使用参数、插件配置、Launch和薄适配器；
- 依赖未完成安装验证、契约未冻结前，不开展W3建图或W5～W8导航运行。
