# M3-W5 IMU单元验证记录

> 日期：2026年8月4日  
> 结论：通过，允许进入M3-W6仿真编码器复核

## 1. 实现范围

- 新增可选`imu_link`、固定`imu_joint`、橙色壳体及Gazebo IMU传感器；
- 独立`imu.launch.py`不依赖底盘控制器，桥接内部`/ai_robot_internal/imu`；
- `imu_adapter.py`规范化为公共`/robot/imu/data`和`imu_link`，使用`imu_stream`；
- 三组协方差从安装后的权威`sensor_model.yaml`注入，不依赖Gazebo默认空协方差；
- 新增静止运行检查、受控旋转符号检查、RViz Frame配置和单元测试。

## 2. 静止运行结果

| 指标 | 结果 | 判定 |
|---|---:|---|
| 消息类型 | `sensor_msgs/msg/Imu` | 与M1一致 |
| Frame | `imu_link` | 与W2一致 |
| 墙钟频率 | 48.706 Hz | 满足50 Hz目标的运行容差 |
| 平均角速度模 | 0.003145 rad/s | 静止噪声合理 |
| 平均Z轴加速度 | 9.8051 m/s² | 重力方向和大小正确 |
| 四元数模 | 1.000000 | 姿态有效且归一化 |
| QoS | Best Effort、Volatile、Depth 20 | `imu_stream` |
| 静态TF | `base_link→imu_link`，z=0.04 m | 与W2一致 |

所有姿态、角速度和线加速度分量均为有限数值；三组协方差与W2冻结值完全一致。

## 3. 旋转方向结果

独立IMU Launch保持无控制器。动态符号测试通过专用`imu_motion.launch.py`显式复用M2已验收
的安全差速控制链，短时发布0.6 rad/s原地左转并在结束时发布零速度。IMU测得正Z峰值
0.548 rad/s，证明俯视逆时针旋转对应正Z角速度，符合REP-103。

## 4. 问题与经验

- Fortress的IMU除通用Sensors系统外，还必须加载`ignition-gazebo-imu-system`；只看到模型和
  桥接节点不能证明传感器已发布，必须在Gazebo Transport确认原始Topic。
- 动态生成模型无法在世界加载阶段绑定`ApplyLinkWrench`持久实体，运行时单次Transport发布
  又可能在发现握手前丢失，因此不采用该路径作为可重复验收证据。
- 静止数据验证和运动符号验证应分离：正常Launch保持传感器独立，动态Launch明确声明复用
  底盘控制链，避免隐藏依赖。
- Gazebo桥接不保证提供项目要求的协方差，公共适配器应从唯一权威配置显式补齐。

## 5. GUI人工验收与可复用流程

用户于2026年8月4日确认Gazebo GUI中可见蓝色小车，并确认小车执行约1.5秒原地逆时针
左转后自动停车。该轮同步测得IMU正Z角速度峰值0.549 rad/s，图形运动方向与消息符号一致，
GUI人工验收通过。

本机同时启动Gazebo GUI、RViz2、模型生成和控制器时，渲染负载会使创建服务超过5秒，进而
导致`gz_ros2_control`未初始化、控制器加载超时。已验证成功且后续可复用的流程为：

1. 使用唯一`ROS_DOMAIN_ID`和`IGN_PARTITION`先启动`imu_motion.launch.py gui:=false
   rviz:=false`；
2. 等待模型生成、`gz_ros2_control`初始化，以及关节状态和差速控制器均激活；
3. 在相同`IGN_PARTITION`下单独运行`ign gazebo -g --force-version 6`，让GUI客户端连接已经
   运行的服务端；
4. 用户确认画面就绪后，再运行受限动作检查脚本；脚本结束和异常路径都必须发布零速度；
5. GUI确认后依次关闭客户端和服务端，避免遗留进程污染后续ROS域。

这套“服务端先行、GUI后接入”流程适用于后续高渲染负载的Gazebo人工验证。若还需要RViz2，
应在模型和控制器稳定后再单独启动，避免与初始化争用GPU和CPU资源。

该流程是对W4相机经验的扩展，不是冲突或替代：W4继续规定GUI只验证视觉语义、无GUI会话
负责消息与性能验收，并解决RViz图像插件的QoS适配；W5进一步规定带控制器和动作时的初始化
顺序。静态、无控制器且本机负载允许时仍可同时启动Gazebo GUI与RViz2，但不得据此测量性能；
只要包含模型生成超时风险、控制器或动作验证，就优先采用服务端先行流程。
