# AI Agent开发规划 v1.0

> 归属：《AI机器人开发项目计划_v1.3》的第二部分详细规划。  
> 范围：AI大模型层、AI—ROS 2接口层及其测试、联调和发布。  
> 启动条件：ROS 2机器人通过G2能力验收。  
> 边界：AI Agent只能调用G2冻结的机器人能力，不能直接控制电机或绕过安全系统。

## 1. 开发目标

在不改变ROS 2机器人内部实现的前提下，建立：

- AI大模型层：理解文字、语音、图片和视频，完成任务理解与高层规划；
- AI—ROS 2接口层：结构化任务、语义目标物理化、合法性校验、能力调用和结果反馈；
- 受约束的任务状态机、能力白名单、权限和安全边界；
- 测试桩、仿真机器人、实体机器人三级联调与回归体系；
- 可观测、可审计、可诊断和可回退的AI任务系统。

AI Agent的定位是：

> 将用户意图转换为受约束的机器人能力调用，而不是替代ROS 2的导航、控制和硬件安全。

## 2. 启动条件与输入基线

只有G2正式通过后才启动本规划。输入至少包括：

- 《ROS 2机器人能力清单》；
- 《ROS 2机器人综合验收报告》；
- 《AI调用接口冻结说明》；
- 《仿真与实体回归测试集》；
- Topic、Service、Action、消息Schema、QoS、TF和错误码；
- 仿真机器人和实体机器人的可重复部署环境。

ROS 2机器人应提供的典型能力：

```text
获取机器人状态
导航到指定位姿
取消导航
检测人员
返回充电点
进入安全停车状态
```

若G2接口不完整或存在阻止接入的严重缺陷，应返回ROS 2规划处理，不在AI层用临时补丁掩盖。

## 3. 系统分层

### 3.1 AI大模型层

负责：

- 文字、语音、图片和视频输入理解；
- 用户意图和任务目标识别；
- 必要的澄清提问；
- 高层任务分解和步骤规划；
- 结构化任务输出；
- 对歧义、危险、越权或能力范围外请求进行澄清或拒绝。

不负责：

- 直接发布`/cmd_vel`；
- 计算底盘实时控制量；
- 替代Nav2路径规划和避障；
- 未经地图或接口确认直接生成物理坐标；
- 绕过AI—ROS 2接口调用机器人。

### 3.2 AI—ROS 2接口层

负责：

- 校验大模型结构化输出；
- 执行Schema、类型、范围和权限检查；
- 将语义地点映射为确认过的物理位姿；
- 调用G2冻结的Topic、Service或Action；
- 管理任务状态、取消、超时、重试和结果反馈；
- 检查机器人、定位和安全状态；
- 形成任务关联ID、审计日志和可诊断错误。

不负责：

- 代替Nav2规划或控制；
- 代替机器人任务管理器；
- 修改硬件安全规则；
- 直接与电机、驱动器或MCU通信。

## 4. 安全边界

AI Agent只能调用能力白名单，例如：

```text
get_robot_status()
navigate_to(location)
detect_person()
cancel_task()
return_to_home()
```

必须禁止：

- 大模型任意执行Shell命令；
- AI直接控制电机或底盘实时速度；
- 绕过安全节点、急停或MCU保护；
- 未校验Schema就调用ROS 2；
- 未检查定位和安全状态就启动运动任务；
- 将不存在或未确认的语义地点直接转换为坐标；
- 在机器人忙碌、急停或状态异常时强制下发任务。

安全控制应至少包括Schema校验、能力白名单、参数范围、状态前置检查、权限控制、超时、取消、审计和人工急停。

## 5. 面向对象与模块化设计

| 对象 | 典型实现 | 主要职责 |
|---|---|---|
| 模型网关 | `AiModelGateway` | 统一接入本地或云端模型、多模态输入及结构化输出 |
| 任务解析器 | `TaskInterpreter` | 从用户输入提取意图、对象、地点和约束 |
| 高层规划器 | `TaskPlanner` | 将目标拆分为白名单能力步骤 |
| Schema校验器 | `TaskValidator` | 校验字段、类型、范围、版本和权限 |
| 语义地点服务 | `SemanticLocationResolver` | 将语义地点映射为已确认的地图位姿 |
| ROS 2能力适配器 | `AiRosBridgeNode` | 将结构化任务转换为Topic、Service或Action调用 |
| AI任务状态机 | `AgentTaskManager` | 管理执行、反馈、取消、超时、重试和结束状态 |
| 审计对象 | `TaskAuditLogger` | 保存输入、结构化任务、调用、结果和异常 |

普通逻辑类尽量与ROS 2通信代码分离，以便离线白盒单元测试。模型供应商、模型版本、仿真机器人和实体机器人均通过适配接口隔离。

## 6. 任务协议

结构化任务至少包含：

- `task_id`：任务唯一标识；
- `schema_version`：协议版本；
- `intent`：任务类型；
- `target`：地点、对象或目标；
- `constraints`：速度、时限、安全和执行条件；
- `steps`：白名单能力步骤；
- `timeout`：任务或步骤超时；
- `on_failure`：失败处理策略；
- `requested_by`：任务来源；
- `trace_id`：跨AI与ROS 2链路关联标识。

示例逻辑：

```text
“去客厅门口看看有没有人”
→ 识别 intent=observe_person
→ 查询“客厅门口”的已确认位姿
→ 生成 NavigateToPose
→ 等待到达
→ 调用 DetectPerson
→ 汇总并反馈结果
```

协议必须定义：

- 成功、失败、取消、超时和拒绝；
- 机器人忙碌、定位无效和安全异常；
- 地点不存在、目标不可达和能力不可用；
- Schema版本不兼容；
- 模型输出不合法或越权；
- 重试条件和禁止重试的安全错误。

## 7. 测试体系

### 7.1 测试层级

| 级别 | 对象 | 方法 | 示例 |
|---|---|---|---|
| A1 代码单元测试 | 普通类和规则 | 白盒、离线、固定输入 | Schema、权限、坐标查询、状态机和错误映射 |
| A2 模型离线评测 | AI大模型层 | 标准任务集、结构化输出检查 | 正确、歧义、非法、危险和越权任务 |
| A3 节点与契约测试 | AI桥接和接口节点 | 模拟消息、Action Server和黑盒测试 | 参数、QoS、调用、取消、超时和错误反馈 |
| A4 测试桩集成 | 完整AI任务链 | 模拟Nav2、感知和机器人状态 | 正常、失败、取消、忙碌和安全异常 |
| A5 仿真端到端 | AI Agent＋仿真机器人 | G2仿真回归场景 | 用户任务到仿真执行结果 |
| A6 实体端到端 | AI Agent＋实体机器人 | 限速、限定区域和安全测试 | 综合任务、异常、急停和恢复 |
| A7 长稳与发布 | 完整系统 | 重复任务、服务中断和资源检查 | 连续运行、恢复、诊断和回退 |

### 7.2 自顶向下联调

```text
用户任务
→ 固定结构化任务
→ AI任务协议
→ 模拟ROS 2能力接口
→ G2冻结的仿真机器人
→ G2验收的实体机器人
```

逐级替换：

```text
测试桩 → 仿真节点 → 实体节点
```

每次替换只改变适配目标，不改变任务协议和上层状态机。

### 7.3 自底向上验证

- Schema、权限和状态机普通类先通过单元测试；
- AI桥接节点通过接口契约测试；
- 语义地点、状态查询和能力适配组合为子系统；
- 模型层接入已通过测试的AI—ROS 2接口；
- 最后进行仿真和实体端到端联调。

## 8. 里程碑

| 里程碑 | 主要目标 | 核心验收 |
|---|---|---|
| M12 AI Agent架构与任务协议 | 定义Schema、白名单、状态机和测试桩 | 合法、非法、歧义和越权样本通过 |
| M13 AI大模型层 | 完成任务理解、高层规划和多模态输入 | 结构化任务输出与异常拒绝达到指标 |
| M14 AI—ROS 2接口层 | 转换并执行受控机器人能力调用 | 校验、语义映射、调用、取消和反馈通过 |
| M15 AI仿真回归联调 | 接入G2冻结的仿真机器人 | 正常、异常、取消和超时场景通过 |
| M16 AI实体机器人联调 | 接入G2验收的实际机器人 | 综合任务和实体安全场景通过 |
| M17 整体稳定化与发布 | 完成长稳、部署、文档和回退 | 可重复部署、连续运行、可诊断和可回退 |

## 9. M12：AI Agent架构与任务协议

主要工作：

- 定义结构化任务Schema、字段、版本和错误码；
- 将G2能力清单转换为AI可调用工具白名单；
- 定义任务状态机、取消、超时、重试和反馈；
- 建立语义地点、物理位姿和目标对象的数据模型；
- 建立模拟Nav2、模拟感知和模拟状态接口；
- 为合法、非法、歧义和越权任务建立测试样本；
- 建立任务关联ID和审计日志规范。

验收重点是协议和安全边界，不要求大模型已经达到最终效果。

## 10. M13：AI大模型层

主要工作：

- 选择本地或云端大模型及多模态方案；
- 设计系统提示词、工具描述和结构化输出约束；
- 实现任务理解、必要澄清和高层步骤规划；
- 拒绝或澄清无效、歧义、危险和能力范围外请求；
- 建立离线任务样本集和自动评测；
- 记录模型、提示词、工具定义和评测集版本。

验收至少检查：

- 任务意图和关键参数提取；
- 结构化输出Schema合规率；
- 歧义任务的澄清行为；
- 危险、越权和能力外任务拦截；
- 模型服务失败、超时和输出截断；
- 同一任务的稳定性和可解释失败原因。

## 11. M14：AI—ROS 2接口层

主要工作：

- 校验Schema、类型、范围、版本和权限；
- 将语义地点映射为确认过的地图位姿；
- 将结构化任务适配为Topic、Service或Action；
- 汇总执行进度、成功、失败、取消和超时结果；
- 检查机器人、定位和安全状态；
- 形成审计日志和跨层任务关联ID；
- 实现测试桩与真实能力适配器的可替换机制。

验收：

- 合法任务正确调用能力；
- 非法、越权和状态不允许的任务被拦截；
- 成功、失败、取消和超时能准确回传；
- 语义地点不存在或未确认时不生成物理命令；
- ROS 2服务中断和重启后行为明确；
- 本层不替代Nav2、控制器和硬件安全。

## 12. M15：AI仿真回归联调

按以下顺序：

```text
固定结构化任务
→ 测试桩
→ G2冻结的仿真机器人能力
→ 完整AI Agent仿真任务
```

综合场景：

```text
用户：“去客厅门口看看有没有人”
→ 大模型生成结构化任务
→ AI—ROS 2接口校验并查询语义地点
→ 调用仿真Nav2导航
→ 调用仿真人员检测
→ 返回执行结果
```

覆盖：

- 地点不存在或未确认；
- 目标不可达和导航失败；
- 感知超时或无结果；
- 任务取消和机器人忙碌；
- 定位或安全状态异常；
- 大模型输出不合规；
- 模型或ROS 2服务中断；
- 多次重复执行和资源占用。

## 13. M16：AI实体机器人联调

保持AI任务协议不变，将调用目标切换为G2验收通过的实体机器人。复用M15测试集，并增加：

- 网络和模型服务中断；
- 实体定位漂移；
- MCU或传感器异常；
- 电量不足；
- 动态人员和障碍物；
- 人工急停及恢复；
- AI任务与人工控制冲突；
- 限速、限定区域和现场安全检查。

发现问题时先判断归属：

```text
AI理解
AI任务协议
AI—ROS 2适配
ROS 2能力接口
实体硬件
```

不允许使用跨层临时补丁掩盖责任边界。

## 14. M17：整体稳定化与发布

交付：

- AI机器人整体安装和部署脚本；
- 提示词、任务Schema、地图、参数和模型版本；
- 操作、调试、维护和安全手册；
- 全部测试报告和已知问题清单；
- 第三方资源、模型及许可证清单；
- 整体发布标签和回退方案。

验收：

- 新环境可以重复部署；
- ROS 2机器人脱离AI后仍可独立运行；
- AI Agent只能调用白名单能力；
- 正常、异常、取消、超时和安全场景通过；
- 综合任务可以重复完成；
- 系统连续运行达到冻结指标；
- 故障可定位到明确层级；
- 发布版本可回退。

## 15. 质量指标与证据

M12建立指标模板，M15前冻结阈值。至少记录：

- 任务意图识别正确率；
- 结构化输出Schema合规率；
- 合法任务规划正确率；
- 歧义任务澄清率；
- 非法、危险和越权任务拦截率；
- 语义地点解析正确率；
- ROS 2能力调用成功率；
- 取消、超时和错误反馈正确率；
- 端到端任务成功率、耗时和失败原因；
- 模型调用时延、成本和服务可用性；
- 连续运行时间、资源占用和恢复情况。

每个里程碑留下：

- 自动测试和离线评测报告；
- 任务样本集及版本；
- 提示词、Schema、模型和配置版本；
- 关键日志和任务关联ID；
- 人工验收记录；
- 已知问题和限制；
- 对应Git提交或标签。

## 16. 主要风险与控制

| 风险 | 控制措施 |
|---|---|
| G2前过早接入AI | G2作为强制启动条件 |
| 大模型输出不稳定 | 结构化输出、Schema校验、离线评测和重试边界 |
| 大模型直接控制底盘 | 能力白名单、AI桥接、安全节点和MCU保护 |
| 语义地点被随意转换为坐标 | 只查询已确认的语义地图数据 |
| 用AI层补丁掩盖ROS 2缺陷 | 问题分层归属，必要时返回ROS 2规划修复 |
| 模型或网络中断 | 超时、取消、降级、清晰反馈和安全停车 |
| 模型升级破坏任务行为 | 锁定模型、提示词和评测集，升级前自动回归 |
| 仿真通过但实体失败 | M15后必须执行M16实体安全联调 |
| 任务日志无法串联 | 统一`task_id`和`trace_id` |
| 成本或时延失控 | 记录调用成本和时延，比较本地与云端方案 |

## 17. 完成判定

AI Agent部分完成必须同时满足：

- M12～M17全部通过；
- AI大模型层和AI—ROS 2接口层职责边界清晰；
- AI只能调用G2冻结的白名单机器人能力；
- 普通类单元测试、模型离线评测、节点契约和集成测试形成自动回归；
- 测试桩、仿真机器人和实体机器人三级联调完成；
- 正常、失败、取消、超时、越权和安全场景均有明确行为；
- 首个综合场景可重复完成；
- 任务输入、结构化任务、ROS 2调用和结果可通过关联ID追踪；
- 模型、提示词、Schema、地图、配置和测试集版本可追踪；
- 系统可部署、可诊断、可维护、可扩展和可回退。
