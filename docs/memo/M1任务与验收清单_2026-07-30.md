# M1“资源、接口与测试基线”任务与验收清单

> 启动日期：2026年7月30日
> 依据：`../planning/AI机器人开发项目计划_v1.5.md`、
> `../planning/ROS2机器人开发规划_v1.1.md`
> 定位：M1执行与验收跟踪清单，不替代正式规划。

## 1. 阶段目标

M1负责为后续M2～M6模拟机器人开发建立可追踪的资源准入规则、仿真与实体统一的
公共接口约束以及可复用的测试骨架。M1不实现完整机器人能力，也不以“能够安装或启动”
代替准入和验收。

## 2. 范围与边界

### 2.1 本阶段范围

- 建立对象、候选资源、仿真实现、实体实现、公共接口和测试方法矩阵；
- 建立第三方资源卡模板、状态流转和准入检查规则；
- 审查Gazebo技术路线并记录兼容性、维护状态、迁移风险和回退方案；
- 定义Topic、Service、Action、消息、QoS、命名、参数和时间规范；
- 定义`map → odom → base_link → sensor_link`坐标系规范；
- 建立单元、节点、Launch、契约和场景测试模板；
- 建立rosbag记录、回放和测试证据模板；
- 完成M1正式验收、归档、交接摘要和基线标签。

### 2.2 本阶段不做

- 不进入M2，不建立正式URDF/Xacro本体或差速底盘运动能力；
- 不开展实体机器人选型定版、硬件写入或运动测试；
- 不正式开发或接入AI Agent；
- 不把未经验证的候选资源标记为“已准入”；
- 不要求一次确定全部硬件品牌，但必须明确接口和选择条件。

## 4. 分项验收清单

### 4.1 对象与资源基线

- [x] 主要机器人对象均有明确职责和“不负责”边界；
- [x] 每个对象至少列出候选成熟资源或自研理由；
- [x] 仿真实现和实体实现的替换关系明确；
- [x] 初步识别公共上层接口、TF和参数影响；
- [x] 每个对象具备最小验证方法、测试层级、风险和替代方案；
- [x] 候选项未被误写为正式准入结论。

### 4.2 资源准入治理

- [x] 资源卡覆盖来源、版本、许可证、维护状态和兼容性；
- [x] 资源卡覆盖安装、依赖、接口、资源占用和安全影响；
- [x] 定义候选、验证中、已准入、已拒绝和延期状态；
- [x] 已准入资源必须具备可复现的最小验证证据；
- [x] 已拒绝或延期资源记录原因、替代方案和重新审查条件；
- [x] 原则上通过配置、适配器或薄封装复用，不直接修改第三方源码。

### 4.3 Gazebo路线

- [x] 核对ROS 2 Humble和Ubuntu 22.04兼容性；
- [x] 核对`ros2_control`、差速底盘和传感器插件路线；
- [x] 记录上游维护状态、支持周期和迁移风险；
- [x] 评估本地开发、CI、教程、模型和社区资源；
- [x] 给出采用方案、锁定版本、替代方案和回退条件；
- [x] 结论经过人工审查。

### 4.4 公共接口、QoS和TF

- [x] Topic、Service和Action使用边界明确；
- [ ] 节点、命名空间、接口、参数和Frame命名规则明确；
- [x] 消息类型、自定义消息条件和版本规则明确；
- [ ] QoS、时间戳、仿真时间、频率和超时规则明确；
- [ ] `map → odom → base_link → sensor_link`发布责任明确；
- [ ] 仿真与实体公共接口一致性可通过契约测试检查。

### 4.5 测试、rosbag和证据

- [ ] 单元、节点、Launch、契约和场景测试均有可运行模板；
- [ ] 测试目录、命名、输入、预期结果和失败证据规则明确；
- [ ] 至少一个C++和一个Python最小测试样例通过；
- [ ] rosbag记录、停止、回放、元数据和命名规则明确；
- [ ] 大型rosbag和原始数据不进入普通Git历史；
- [ ] 测试结果能关联软件版本、配置、提交号和执行环境。

## 5. M1完成判定

只有同时满足以下条件，M1才可申请正式验收：

1. M1-W1至M1-W7全部完成并通过对应检查；
2. 资源选择、接口、QoS、TF和测试基线之间不存在已知冲突；
3. 所有关键结论均有来源、版本、验证证据和回退方法；
4. 自动检查通过，需要人工判断的项目有明确审查结论；
5. 阻塞项已关闭，或形成经用户确认的延期和风险处置结论；
6. 形成M1阶段规划快照、正式验收记录、验证证据索引和遗留问题；
7. 验收通过后完成`docs/backs/milestones/M1/`归档和M1阶段交接摘要；
8. 经用户明确授权后创建M1基线标签。

M1未通过前不得进入M2。
