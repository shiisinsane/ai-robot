# M4“运动、感知与安全集成”任务与验收清单

> 启动日期：2026年8月5日
> 依据：`../planning/AI机器人开发项目计划_v1.11.md`、
> `../planning/ROS2机器人开发规划_v1.7.md`
> 输入基线：M3正式归档`../backs/milestones/M3/`、M1接口版本`m1.v1`
> 定位：M4执行与验收跟踪清单，不替代正式规划。

## 1. 阶段目标

把M2底盘和M3雷达、相机、IMU、编码器从独立单元组合为可统一启动、持续观察和安全停止的
仿真机器人系统；建立局部状态估计、基础感知数据链、诊断与安全监督，并验证启动顺序、时间
同步、QoS、TF完整性、资源占用、故障传播和安全停车。

M4不实现SLAM、地图、全局定位、Nav2、目标识别、实体机器人或AI Agent。

## 3. 关键验收条件

- [x] M4范围和非目标明确，不提前进入M5；
- [x] 状态估计、图像处理和诊断候选资源来源、版本、许可证及回退方法可追踪；
- [ ] 所有M2/M3单元可统一启动、按依赖顺序就绪并干净停止；
- [ ] `odom → base_link`动态TF始终只有一个权威发布者；
- [ ] 编码器与IMU融合输出连续、有限、方向正确并具备合理协方差；
- [ ] 机器人运动时雷达数据可通过完整TF链正确解释；
- [ ] 相机基础处理输出保持时间戳、Frame、分辨率和编码契约；
- [ ] 安全监督独占公共命令入口，关键数据超时或故障时受控停车；
- [ ] 故障状态、原因、锁存和清除可通过标准诊断及安全状态观察；
- [ ] 全系统同时运行时频率、实时因子和资源占用达到冻结指标；
- [ ] M1接口、M2底盘安全和M3传感器回归无退化；
- [ ] 系统回归、最小rosbag、回放、日志、配置快照和SHA-256完整；
- [ ] 全部测试不连接实体设备或AI Agent。

## 4. 完成判定

只有M4-W1～W9全部完成、上述条件关闭、阻塞项清零或形成经用户确认的延期处置，才可进入
M4-W10正式验收。正式验收通过后才归档M4；未经用户明确授权不启动M5，不创建Git提交、
推送或标签。
