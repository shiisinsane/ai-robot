# M1数据与证据规范

> 版本：M1-W7首版
> 状态：已确认
> 适用范围：M1及后续ROS 2机器人测试
> 技术基线：Ubuntu 22.04、ROS 2 Humble、rosbag2 0.15.16

## 1. 目标与边界

W7规定测试数据如何录制、正常停止、检查、回放、索引和保存，使测试结论能够关联代码、
配置、环境和原始证据。W7不录制实体机器人数据，不把大型rosbag纳入普通Git历史，也不
替代W6的测试判定。

rosbag用于复现输入和保存运行过程，不能仅凭“成功录制”判定功能通过。正式结论仍由自动
断言、场景验收和人工检查共同给出。

## 2. 数据分类

| 类别 | 示例 | Git策略 |
|---|---|---|
| 小型确定性测试输入 | YAML、JSON、短文本、参数样例 | 可放入`test_data/` |
| 测试模板和证据索引 | 清单模板、报告、SHA-256、外部位置 | 可提交 |
| 构建与普通运行日志 | `build/`、`install/`、`log/` | 本地忽略 |
| rosbag及原始传感器数据 | `.db3`、`.mcap`、图像、视频 | 不进入普通Git |
| 模型权重和大型地图 | 权重、原始地图数据 | 外部存储或发布附件 |
| 敏感数据 | 凭据、私有地址、人员隐私、室内布局 | 默认禁止共享，先审查和脱敏 |

大型数据使用受控外部存储、发布附件或经审查的Git LFS。仓库中只保存来源、版本、大小、
SHA-256、访问条件和复现方法，不保存本地绝对私有路径或访问令牌。

## 3. rosbag录制配置

机器可读配置位于`config/common/rosbag_recording.yaml`。首版固定：

- 存储：`sqlite3`；
- 序列化：`cdr`；
- 压缩：按文件使用`zstd`；
- 单文件最大`2 GiB`；
- 最长每`300 s`切分；
- 最大缓存`100 MiB`；
- 禁止`ros2 bag record -a`无差别录制；
- 只录制配置档明确列出的Topic；
- 输出根目录：被Git忽略的`artifacts/rosbags/`。

### 3.1 配置档

| 配置档 | 用途 | 主要必需Topic |
|---|---|---|
| `core` | 基础状态和安全 | TF、里程计、诊断、安全停车状态 |
| `navigation` | SLAM、定位和导航 | 继承`core`，增加雷达和地图 |
| `perception` | 图像感知 | 继承`core`，增加彩色图像及标定 |

仿真录制必须包含`/clock`并使用仿真时间。实体录制不得使用`--use-sim-time`。
`/rosout`、`/parameter_events`以及名称疑似包含密钥、令牌或密码的Topic禁止默认录制。

### 3.2 命名

目录格式：

```text
YYYYMMDD_HHMMSS_<mode>_<scenario>_<commit8>
```

示例：

```text
20260731_153000_sim_lidar_timeout_2677629a
```

`mode`只能是`sim`或`real`。`scenario`使用2～48位小写字母、数字、下划线或连字符，
必须表达测试目的，不能使用`test1`、`new`等无意义名称。

## 4. 录制和停止

统一入口：

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ROS_DOMAIN_ID=61 python3 scripts/record_rosbag.py \
  --mode sim \
  --profile navigation \
  --scenario lidar_timeout
```

脚本会：

1. 读取录制配置档并展开继承的Topic白名单；
2. 生成包含时间、模式、场景和提交号的目录；
3. 应用存储、压缩、切分、缓存和仿真时间参数；
4. 将ROS日志写入`artifacts/rosbags/_ros_logs/`；
5. 正常停止后检查`metadata.yaml`、消息数、持续时间和必需Topic。

使用`Ctrl-C`正常停止，使rosbag刷新缓存并写入`metadata.yaml`。不得使用`kill -9`作为
普通停止方式。意外终止后先保留原目录，记录异常，再使用`ros2 bag reindex`尝试恢复；
恢复后的数据必须重新检查，不能默认视为完整。

## 5. 完整性检查

单独检查：

```bash
python3 scripts/check_rosbag.py \
  artifacts/rosbags/<bag目录> \
  --profile navigation
```

检查通过至少表示：

- 目录和`metadata.yaml`存在；
- 总消息数和持续时间大于零；
- 配置档要求的Topic全部存在；
- 每个必需Topic至少有一条消息。

这不保证频率、内容和场景结果正确。正式测试仍需使用W6测试验证频率、时间戳、TF、安全
超时和业务结果。

## 6. 回放

回放前先执行完整性检查，并使用独立`ROS_DOMAIN_ID`。默认只回放当前测试需要的Topic，
避免污染其他ROS图。

仿真/离线算法回放：

```bash
ROS_DOMAIN_ID=62 ros2 bag play <bag目录> \
  --clock 100 \
  --disable-keyboard-controls
```

订阅回放数据的节点设置`use_sim_time: true`，并确保ROS域内没有Gazebo或另一个播放器
同时发布`/clock`。

实体时间数据的观察性回放默认不发布`/clock`。回放绝不能连接实体底盘控制链；涉及
`/robot/cmd_vel`时必须重映射到测试命名空间或排除该Topic：

```bash
ros2 bag play <bag目录> \
  --topics /robot/odom /robot/scan \
  --disable-keyboard-controls
```

循环、倍速、起始偏移、Topic重映射和QoS覆盖必须记录在证据清单中，因为它们会改变复现
条件。回放完成后记录退出码、接收消息数和实际测试结果。

## 7. 测试证据清单

机器清单模板：

```text
test_data/templates/evidence_manifest.yaml
```

人工阅读模板：

```text
docs/templates/M1测试证据记录模板.md
```

正式证据至少包含：

- 唯一证据ID、里程碑、测试名称、日期和执行人员；
- Git提交号、工作区状态、接口版本和配置文件；
- 操作系统、ROS版本、RMW、`ROS_DOMAIN_ID`和运行模式；
- 命令、开始/结束时间、通过/失败/跳过数量；
- 日志、rosbag、截图或报告的外部位置、大小和SHA-256；
- 敏感信息检查、已知问题、人工检查和回退方法。

验证清单：

```bash
python3 scripts/check_evidence_manifest.py <evidence_manifest.yaml>
```

证据清单中的`passed`只记录测试工具给出的结论，不得由录制脚本自动填写。

## 8. 保存、校验和清理

- 每个外部证据文件计算SHA-256，移动或下载后重新校验；
- 阶段验收证据至少保留到对应里程碑归档及其规定保留期结束；
- 删除或替换外部证据前，先更新索引和已知问题；
- 不在清单中写密码、令牌、私有服务地址或可直接访问的临时签名链接；
- 人员图像、语音和室内地图按敏感数据处理，未经审查不共享；
- 空间不足时先停止录制并保留已完成分片，不通过删除正在写入的文件释放空间；
- 普通临时验证数据可以清理，但正式验收引用的数据必须有可访问副本。

## 9. W7验证与W8入口

W7最小验证使用无运动能力的测试Topic完成：

1. 录制多条`std_msgs/msg/String`消息；
2. 通过`ros2 bag info`和检查脚本确认元数据、数量及持续时间；
3. 将Topic重映射后回放；
4. 由独立订阅者收到预期消息；
5. 验证证据清单模板的成功和失败分支；
6. 确认rosbag、日志和`artifacts/`不会进入Git。
