# M5-W4地图保存与重载验证记录

> 日期：2026年8月6日  
> 结论：通过，允许进入M5-W5地图定位。

## 1. 完成内容

- 在M5 SLAM Launch中接入Nav2 Map Saver Server及Lifecycle Manager；
- 新增地图保存守卫，对外保持M1冻结的`/robot/map/save_map`和`nav2_msgs/srv/SaveMap`；
- 公共调用只接受1至64位字母、数字、下划线和连字符组成的地图名称，保存目标始终限制在
  Launch指定目录；路径、`..`、嵌套目录和过长名称均拒绝；
- 内部Map Saver Service不作为公共接口，保存超时冻结为10秒，地图格式为PGM/trinary，
  free/occupied阈值为`0.25/0.65`；
- 新增离线YAML、PGM、目录、尺寸、分辨率、阈值和SHA-256检查器；
- 新增独立Map Server重载Launch，重载时不启动SLAM，避免地图和`map → odom`权威冲突。

## 2. 保存验证

非法请求：

```text
map_url: ../escape
result: false
```

合法请求`map_url: m5_w4_verified`通过公共Service保存：

```text
result: true
图像：128x118，分辨率0.050 m
原点：[-3.2, -2.95, 0]
SHA-256 YAML: 9cca580f427409ff7bfd46f5bff6f0ef613127958219bc4f278e599c78f03b71
SHA-256 PGM: 8330c2f81c276d55e42796960f6b92b6c38171db36865349200ca25caadd2b01
```

验证文件位于临时目录`/tmp/ai_robot_m5_w4_maps`，不纳入Git；正式回归证据将在W10生成到
受忽略的`artifacts/`并登记哈希。

## 3. 进程重启与重载验证

完全关闭Gazebo、SLAM、Map Saver和M4节点后，独立启动：

```bash
ros2 launch ai_robot_sim m5_map_reload.launch.py \
  map:=/tmp/ai_robot_m5_w4_maps/m5_w4_verified.yaml
```

Nav2 Map Server生命周期自动完成configure和activate，日志确认读取同一PGM。重载后的
`/robot/map`为`128×118`、`0.05 m`、原点`(-3.2,-2.95,0)`，与保存文件一致；只有
`/robot/map_server`一个发布者，QoS为Reliable与Transient Local。

## 4. 自动验证与负向覆盖

- 安全名称解析、6类非法名称、图像越界、合法PGM/YAML共9项W4单元检查通过；
- W4与既有M5导航、仿真资产定向检查共29项通过；
- 实际运行发现Humble Map Saver的服务固定在节点全名`/robot/internal_map_saver/save_map`，
  已按运行图修正守卫客户端，未改变公共Service契约。

## 5. 边界与下一入口

W4证明地图可以安全保存并在全进程重启后原样加载，但Map Server只提供静态地图，不估计机器人
位姿，也不发布定位模式的`map → odom`。W5将接入AMCL、初始位姿输入和收敛/稳定性检查。
