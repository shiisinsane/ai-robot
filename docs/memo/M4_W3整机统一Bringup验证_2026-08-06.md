# M4-W3整机统一Bringup验证记录

> 日期：2026年8月6日
> 结论：通过，允许进入M4-W4编码器与IMU状态估计

## 1. 实现范围

- 新增`m4_integrated.sdf`统一仿真世界，同时加载物理、渲染传感器和IMU系统；
- 新增`integrated_bringup.launch.py`，统一启动Gazebo、机器人描述、底盘控制器、雷达、RGB
  相机、IMU和编码器数据链；
- 新增`controllers_m4.yaml`，整机模式关闭差速控制器TF；
- 参数化控制器里程计重映射：M2独立模式仍输出`/robot/odom`，M4整机模式输出
  `/robot/internal/base_odom`；
- 整机模式将M2安全过滤器输入改为`/robot/safety_cmd_vel`，为W7安全监督器保留公共
  `/robot/cmd_vel`唯一所有权，不形成命令旁路；
- 未提前接入EKF、`image_proc`或M4安全监督逻辑。

## 2. 启动与运行图验证

在隔离的`ROS_DOMAIN_ID=164`和独立Gazebo分区中启动统一Bringup，结果如下：

- `joint_state_broadcaster`和`diff_drive_base_controller`均为`active`；
- `/robot/scan`发布`LaserScan`，Frame为`laser_link`；
- `/robot/camera/color/image_raw`发布`640×480 rgb8`图像，Frame为
  `camera_color_optical_frame`；
- `/robot/imu/data`发布有限IMU数据及冻结协方差，Frame为`imu_link`；
- `/robot/joint_states`持续发布左右轮编码器状态；
- `/robot/internal/base_odom`由差速控制器唯一发布；
- `/robot/cmd_vel`无订阅旁路，`cmd_vel_safety_filter`唯一订阅
  `/robot/safety_cmd_vel`；
- Ctrl-C后适配器、桥接、状态发布器和控制器完成关闭，Launch返回码为0。

## 3. 自动验证

- 4个ROS 2软件包构建通过；
- 包内32项测试通过；
- 仓库级39项测试通过；
- Xacro整机展开、Python语法、离线资源检查和`git diff --check`通过；
- 首次沙箱内运行因本地网络套接字权限被拒绝，随后在获准的沙箱外隔离环境中验证通过；
- 未连接实体设备或AI Agent。

## 4. 已知边界

- W3只验收统一启动、运行图、端点隔离和停止流程，不宣称融合里程计、图像处理或故障停车
  已通过；
- 整机模式已关闭底盘`odom → base_link`TF，W4接入EKF前该动态边暂不发布；
- Gazebo仍报告已知的根Link惯量KDL提示和无头渲染EGL提示，不影响本次数据链验证；
- 性能门限、实时因子、CPU和内存留待W8正式测量。

## 5. 下一入口

M4-W4接入`robot_localization/ekf_node`，融合内部底盘里程计与IMU，恢复公共
`/robot/odom`并由EKF唯一发布`odom → base_link`；随后验证静止、直行和转向场景中的连续性、
方向、有限值与协方差。M4正式验收通过前不得进入M5。
